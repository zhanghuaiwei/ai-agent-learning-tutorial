## 1. 这套教程要解决什么问题

最终目标不是“会调用 LangChain 的几个 API”，而是让学习者能够独立完成一个可演示、可测试、可部署、可解释设计取舍的 Agent 应用，并能在面试中证明以下能力：

1. 能把业务问题拆成模型、工具、知识、状态、流程和安全边界。
2. 能用 Python 实现 Agent 后端，而不是只完成 Notebook 或一次性脚本。
3. 能实现工具调用、结构化输出、记忆、RAG、工作流与人工审批。
4. 能用 LangChain 快速搭建常规 Agent，用 LangGraph 控制复杂、有状态的流程。
5. 能通过 LangSmith 或等价方案追踪、调试、评测和持续改进 Agent。
6. 能处理超时、重试、幂等、权限、提示词注入、成本、延迟和失败恢复。
7. 能将应用封装成 API、持久化数据、容器化部署，并提供测试和项目文档。
8. 能在面试中讲清楚原理、架构、指标、事故案例和技术权衡。

## 2. 对目标岗位的判断

### 2.1 岗位定位

目标应定位为 **AI Agent 应用开发工程师 / 大模型应用开发工程师**，而不是大模型训练算法工程师。

应用开发岗位的核心价值是把不稳定、非确定性的大模型能力接入真实业务，做成可控、可测、可维护的系统。近期岗位样本反复出现以下能力组合：

- Python 后端与工程基础；
- 大模型 API、Prompt、结构化输出和 Tool Calling；
- LangChain、LangGraph 等 Agent 框架；
- RAG、Embedding、向量数据库、召回与重排；
- 任务规划、记忆、工作流、多 Agent、人机协作；
- MCP 与业务工具接入；
- 评测、日志追踪、监控、安全、成本与性能；
- REST API、数据库、缓存、消息队列、Docker 和上线交付。

这意味着“能跑通 Agent Demo”只能达到入门线；面试竞争力主要来自 **工程闭环、评测意识和一个讲得深的项目**。

### 2.2 不作为主线的内容

以下内容不应抢占 G0～G8 主线时间，但可在 G9/G10 按目标岗位继续深入：

- 前端基础、React/Vue/TypeScript 基础；
- 从零训练 Transformer；
- 大篇幅高等数学推导；
- CUDA、分布式训练和底层推理优化；
- 同时精通 CrewAI、AutoGen、LlamaIndex、Dify 等所有框架；
- 为了“全面”而学习大量没有项目落点的 NLP 算法。

这些内容保留为选修或面试概览。主线聚焦 **Python + FastAPI + LangChain + LangGraph + LangSmith + RAG + MCP + 工程化**。

## 4. 教程的最终设计思想

### 4.1 以岗位输出倒推，而不是以框架目录正推

每个知识点必须对应至少一种岗位输出：代码、测试、指标、架构决策记录、故障复盘或面试回答。不能转化为输出的知识只做资料索引，不占用主线篇幅。

### 4.2 先理解原生能力，再使用框架

学习顺序为：

1. 直接调用模型 API；
2. 手写结构化输出与 Tool Calling 循环；
3. 用 LangChain 重构常规 Agent；
4. 用 LangGraph实现显式状态与复杂流程；
5. 用 LangSmith 做追踪和评测；
6. 用 MCP 标准化外部工具与数据连接。

这样既能理解框架帮我们解决了什么，也不会在框架版本变化后失去独立开发能力。

### 4.3 “一个主项目螺旋升级 + 若干小练习”

教程不做十几个互不相关的聊天机器人。建议从第一个月开始持续演进同一个项目：

**企业知识与任务执行 Agent**

它会依次获得以下能力：

`模型对话 → 结构化输出 → 工具调用 → 文档 RAG → 状态图 → 记忆 → 人工审批 → MCP → 评测 → 部署`

每阶段仍会安排 30～90 分钟的小练习，用来隔离验证单个概念；每月形成一个可以运行和演示的里程碑版本。

### 4.4 评测先行

Agent 输出具有非确定性，不能以“我试了几个问题，感觉还行”作为完成标准。每个 Demo 都需要：

- 明确成功条件；
- 最小测试集或评测集；
- 正常、边界和攻击样例；
- 任务成功率、工具选择正确率、引用正确性、延迟、成本等指标中的至少一项；
- 版本变更前后的回归结果。

### 4.5 官方文档优先并控制版本漂移

每章资料按以下顺序组织：

1. 官方概念文档；
2. 官方 API Reference；
3. 官方示例或维护者教程；
4. 高质量论文/课程；
5. 社区文章只作为补充，并标注版本与风险。

每个框架章节都记录 `验证日期、适用版本、过时 API 提醒`。正式教程生成时应锁定依赖版本；面试前再安排一次“版本更新检查”。

### 4.6 教程与作品集同时生长

每阶段都输出可沉淀到简历或 GitHub 的材料：

- README 与架构图；
- API 和数据模型说明；
- 测试/评测报告；
- Architecture Decision Record（ADR）；
- 失败案例和性能优化记录；
- 2～3 分钟演示脚本；
- 对应面试题与 STAR 表达。

## 5. 24 周压缩排期参考

> 默认假设：该排期不限制完整教程范围，实际进度以能力门槛为准。

### 阶段 0：基线测评与环境准备（第 1 周）

- Python、HTTP、SQL、Git、Docker 和 LLM 概念摸底；
- 建立 Python 项目、依赖管理、代码质量与测试环境；
- 直接调用一个 OpenAI-compatible 模型；
- 输出：个人差距清单、学习节奏、最小 CLI 对话程序。

### 阶段 1：Python Agent 后端必需能力（第 2～4 周）

- Python 类型系统、数据类、异常、生成器、装饰器和上下文管理器；
- `async/await`、并发控制、超时和重试；
- Pydantic、FastAPI、pytest、日志、配置和环境变量；
- HTTP/SSE、REST、Webhook；
- 输出：带结构化输入输出、流式响应、测试和错误处理的模型网关 API。

### 阶段 2：LLM 应用与单 Agent 基础（第 5～7 周）

- LLM 应用必需原理：Token、上下文窗口、采样、幻觉、Embedding；
- Message、Prompt、Context Engineering、结构化输出；
- Function/Tool Calling、工具 Schema、Agent Loop、ReAct 的工程含义；
- 手写最小 Agent Loop，再用 LangChain 重构；
- 输出：可调用搜索、计算和业务 API 的任务助手。

### 阶段 3：RAG 与知识系统（第 8～11 周）

- 文档解析、清洗、元数据、切分；
- Embedding、向量检索、BM25/混合检索、过滤、重排；
- Query 改写、引用、拒答、上下文压缩；
- RAG 评测：检索与生成分开测；
- 输出：有引用、可评测、能解释失败原因的企业知识助手。

### 阶段 4：LangGraph 与有状态工作流（第 12～15 周）

- State、Node、Edge、Reducer、Command、路由与循环；
- Checkpoint、Thread、短期/长期记忆；
- Interrupt、Human-in-the-loop、恢复、回放和幂等；
- 子图、并行、Supervisor/Router 等多 Agent 模式及适用边界；
- 输出：能暂停审批、失败恢复、保留任务状态的研究/执行 Agent。

### 阶段 5：LangSmith、评测、安全与可靠性（第 16～18 周）

- Trace、Run、Thread、Dataset、Experiment；
- 单元测试、轨迹评测、LLM-as-a-Judge 与人工抽检；
- Prompt Injection、Tool Poisoning、越权、数据泄漏；
- 允许列表、最小权限、高风险写操作确认、输出校验；
- 输出：自动评测集、回归报告、红队样例和安全设计说明。

### 阶段 6：MCP 与生产工程化（第 19～21 周）

- MCP 的 Host、Client、Server、Tools、Resources、Prompts；
- 实现一个只读 MCP Server，并接入主项目；
- PostgreSQL/pgvector、Redis、任务队列的最小必要使用；
- Docker、CI、健康检查、可观测性、限流、缓存、成本与降级；
- 输出：容器化、可部署、具备审计日志的 Agent 服务。

### 阶段 7：企业级项目收口与面试交付（第 22～24 周）

- 完成端到端架构、测试、评测与部署；
- 至少一次故障注入和性能优化；
- 项目 README、架构图、ADR、评测报告、演示视频脚本；
- 准备项目深挖、Agent 系统设计、Python 后端和常见算法题；
- 输出：可用于简历的完整作品与第一轮模拟面试记录。

### 面试冲刺

- 每周一次模拟面试；
- 根据 JD 做能力映射和项目表达改写；
- 回顾高频原理题、场景设计题与项目事故题；
- 只修复暴露出的短板，不再无边界扩展新框架。

## 6. 阶段 Demo 与企业级实战项目

| 里程碑 | Demo | 必须证明的能力 |
| --- | --- | --- |
| M1 | 结构化模型网关 | Python 工程、API、流式响应、异常和测试 |
| M2 | 工具调用任务助手 | Tool Schema、调用循环、超时、重试和审计 |
| M3 | 有引用的知识助手 | RAG、检索评测、引用、拒答和数据处理 |
| M4 | 可恢复的工作流 Agent | LangGraph、状态、记忆、中断、审批、恢复 |
| M5 | 可观测的安全 Agent | LangSmith、评测集、回归、安全与成本指标 |
| Final | 企业知识与任务执行 Agent | MCP、生产后端、部署、完整工程闭环 |

企业级实战项目建议至少包含：

- FastAPI + SSE 接口；
- LangChain 常规组件与 LangGraph核心编排；
- 文档入库、检索、重排、引用和拒答；
- 3 个以上有真实价值的工具；
- 短期状态与持久化记忆；
- 至少一个高风险操作的人工审批；
- 一个自建或接入的 MCP Server；
- LangSmith Trace 和一套可重复执行的评测集；
- 超时、重试、幂等、权限、限流和审计日志；
- PostgreSQL/pgvector、Redis（按场景选择）；
- Docker、CI、测试、部署文档和架构决策记录。

前端只提供接口契约和 Agent 交互设计要求，不讲前端基础。界面可自行实现，这会成为作品集加分项。

## 8. 每篇教程的固定结构

每篇教程都遵循统一模板：

1. 本节对应的岗位能力；
2. 学习目标与预计时长；
3. 前置知识；
4. 核心概念与最小原理；
5. 可运行示例与逐步解释；
6. 常见错误、排查方法与版本提醒；
7. 基础练习、工程练习、开放挑战；
8. 验收标准与自动测试建议；
9. 紧随题目的参考答案或解题思路；
10. 面试追问；
11. 官方资料来源与验证日期；
12. 本节产出如何并入主项目。

练习分三级：

- A 级：确认概念和 API；
- B 级：独立完成一个工程任务；
- C 级：处理开放问题、故障或架构权衡。

“完成一章”的标准不是看完，而是：练习通过、能解释、能从空白重建核心部分，并完成一次失败复盘。

## 9. 资料依据

以下资料用于本设计稿的方向校验；正式教程会为每章补充更具体的官方链接。

### 官方技术资料

- [OpenAI Agents SDK Quickstart](https://developers.openai.com/api/docs/guides/agents/quickstart)：当前官方教程同时提供 Python/JavaScript，并把工具、专用 Agent、编排、护栏、状态、可观测性和评测列为 Agent SDK 学习面。
- [LangChain Agents](https://docs.langchain.com/oss/python/langchain/agents)：当前 LangChain Agent 构建在图运行时之上，覆盖工具、结构化输出、上下文、持久化、中间件与人工介入。
- [LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)：说明 Checkpointer、Thread 和 Store 在状态持久化与跨会话记忆中的作用。
- [LangSmith Evaluation Concepts](https://docs.langchain.com/langsmith/evaluation-concepts)：强调非确定性 LLM 应用需要从开发前评测延伸到生产监控。
- [MCP Architecture](https://modelcontextprotocol.io/specification/2025-06-18/architecture)：定义 Host、Client、Server 以及能力协商和安全边界。

### 岗位样本（用于观察市场要求，不视为官方标准）

- [阿里巴巴大模型应用开发工程师岗位样本](https://www.jdwatch.work/jobs/j1ohuw8wq)：涉及 Tool Calling、记忆、多 Agent、RAG、评测、监控、MCP 与高可靠架构。
- [AI Agent 应用工程师岗位样本](https://www.shushuqiuzhi.com/position/435060)：涉及 Python 后端、LangChain/LangGraph、RAG、数据库、缓存、消息队列、容器化、追踪与安全。

## 10. 最终确认结果

1. 每周学习时间为 15 小时，24 个核心周约有 360 小时可用。
2. 企业级项目、简历材料和第一版面试题库必须在开始投递前完成。
3. 目标城市为西安，行业与公司规模不限，但项目方向必须能映射到未来五年大概率持续与 AI 深度融合的产业。
4. Python 是必须掌握的 Agent 主语言；Java 不与 Python 竞争，而是在后期作为可插拔业务服务增强线。
5. 模型使用千问与 DeepSeek，API 费用无固定上限；仍通过 Usage、成本、调用次数、缓存、录制回放和离线测试识别浪费并保证测试可重复。
6. 本地不运行 Docker 和本地大模型。开发环境使用轻量 Python 虚拟环境、嵌入式数据库和远程模型 API；容器知识通过 Dockerfile、CI 构建和部署说明完成验证。
7. 项目被定义为“企业级实战项目”，不是毕业作业。行业背景选择西安重点发展的先进制造、航空航天、低空经济与工业软件的交集。
8. 教程采用完整长教程，强调深层原理、工程推导、常见失败与排查；练习答案直接放在对应题目之后。
9. 除无法合理翻译的技术名词、API 名称和代码标识符外，全部使用简体中文；英文官方资料提供中文阅读指引。
10. 设置每周 2 小时的横向基础补给线覆盖数据结构、算法、网络、操作系统和数据库，而不是最后突击。
11. 源码随教程逐阶段创建，不预先给出完整成品。
12. 企业级项目以业务完成度、稳定性和评测证据为核心，同时完整教授复杂架构的原理与适用边界，不让最终项目限制教程知识范围。

正式执行说明见 `README.md`、`01-总览与使用方式/01-最终课程架构.md`、`01-总览与使用方式/02-24周学习计划.md` 和 `01-总览与使用方式/03-企业级项目蓝图.md`。
