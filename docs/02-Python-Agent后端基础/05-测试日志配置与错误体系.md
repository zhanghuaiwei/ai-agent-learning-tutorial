# 测试、日志、配置与错误体系

> 预计 6 小时｜产出：没有真实模型也能稳定回归的服务骨架。

## 1. 测试分层

- 单元测试：确定性函数、路由、Schema、成本计算。
- 集成测试：数据库、HTTP 适配器、模型网关边界。
- 端到端测试：从 API 到模型/工具替身的链路。
- Agent 评测：回答质量、轨迹、检索和安全。

普通测试回答“代码是否按约定运行”，评测回答“概率系统是否足够好”，不能互相替代。定义自有 `ChatModel` Protocol，Fake 返回固定消息或工具调用；CI 禁止访问收费 API。

## 2. 错误与日志

异常分领域错误、外部依赖错误、系统错误；API 层统一翻译，不要到处吞 `Exception`。每条结构化日志包含服务、环境、`request_id/run_id/thread_id`、事件名、耗时、结果码；用户原文和文档正文默认不记录。

配置按“默认值 < 配置文件 < 环境变量”覆盖，启动时验证。

## 3. 项目任务

建立 `tests/unit`、`tests/integration`、`tests/e2e`，覆盖成功、限流、超时、非法 JSON、取消；加入 JSON 日志与全局异常处理器。

## 4. 练习与答案

### 练习 1：为什么 CI 不调用真实模型？

**答案：**费用、网络和随机性会让测试不稳定；真实调用放受控评测。

### 练习 2：日志记录完整 Prompt 有何风险？

**答案：**可能泄露隐私、企业文档、系统提示和工具结果；应脱敏、最小化、限期保存。

## 5. 验收与资料

断网可跑普通测试，错误含稳定码与 `request_id`，日志无 Key。参考 [pytest](https://docs.pytest.org/en/stable/)、[monkeypatch](https://docs.pytest.org/en/stable/how-to/monkeypatch.html)、[logging](https://docs.python.org/3/library/logging.html)。
