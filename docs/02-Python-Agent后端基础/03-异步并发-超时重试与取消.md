# 异步并发、超时、重试与取消

> 所属阶段：第 3 周  
> 预计用时：7～8 小时  
> 项目产出：异步模型网关与 `ReliableInvoker` 可靠执行器  
> 资料验证日期：2026-09-02

## 1. 本章从哪里开始

第 2 章结束时，项目状态是：

- `schemas.py`：Pydantic 契约（`ChatResult`、领域模型、工具 IO、`ToolResult` 信封）；
- `gateway.py`：`ModelGateway` Protocol、两个同步网关、唯一的客户端构造点 `_build_client`；
- `fakes.py`：`FakeGateway`，记录 `chat_calls` 供观测；
- 9 个离线测试全绿，零真实 API 调用。

但网关仍然是**同步**的。三件事马上会出问题：

1. 一次设备诊断要同时查告警（`get_alarm`）和查手册（`search_manual`）。串行执行时总延迟 = 两者之和；并发执行时约等于较慢的那个。CLI 里这只是慢一点，到第 4 周做成 HTTP 服务后，同步阻塞会拖垮整个进程的吞吐；
2. 第 1 章刻意关闭的 SDK 自动重试（`max_retries=0`）一直没有偿还。现在要按自己的规则重试：只重试瞬时错误、次数有限、退避带抖动、每次重试可观测；
3. 用户关掉页面后，上游模型调用应该被取消，而不是继续烧钱。

本章完成后你应该能回答：

1. `async` 为什么不会让代码变快，却能让 I/O 等待重叠？
2. 连接超时、读取超时、总预算超时分别管什么？
3. 哪些错误值得重试，哪些重试只会放大故障？
4. `CancelledError` 为什么不能吞掉？

## 2. 本章完成标准

必须同时满足：

- 网关迁移到 `AsyncOpenAI`，`ModelGateway` Protocol 变为异步签名，`main.py` 用 `asyncio.run` 适配；
- `get_alarm` 与 `search_manual` 通过 `TaskGroup` 并发执行，一处失败全组取消；
- `ReliableInvoker` 提供：总超时、最多两次重试、指数退避加抖动、并发信号量、取消传播、耗时统计；
- `FlakyGateway` 能模拟 429、超时挂起、永久 400、取消四种行为；
- 全部测试离线通过；重试、退避、取消、并发上限各有对应测试。

## 3. 心智模型：Agent 是 I/O 密集型服务

Agent 服务的时间花在哪？发起模型调用后等待、查询数据库后等待、调用工具 API 后等待。**大部分时间在等待 I/O，而不是计算**。

三种并发模型的对比：

| 模型 | 切换成本 | 适用场景 |
| --- | --- | --- |
| 多进程 | 最高（独立内存空间） | CPU 密集，绕过 GIL |
| 多线程 | 中等（GIL 限制并行计算） | 阻塞 I/O 库的兼容方案 |
| 协程（asyncio） | 最低（函数级挂起恢复） | 大量并发 I/O 等待 |

`async` 的本质：**当一个协程在等待 I/O 时，事件循环切换去运行别的协程**。它不会让任何一次请求变快，但让等待可以重叠。反过来说，如果在协程里调用了一个同步阻塞函数（比如同步 SDK 的网络请求、`time.sleep`、大文件解析），整个事件循环都会卡住——所有并发瞬间归零。这就是本章必须把网关整体迁移到异步，而不是“局部加个 async”的原因。

诊断口诀：`async` 不加速计算；阻塞调用是异步世界的毒药；CPU 重活要么用线程池隔离，要么换进程。

## 4. 迁移网关到异步

### 4.1 Protocol 的签名变化

```python
from collections.abc import AsyncIterator

from agent_service.schemas import ChatResult


class ModelGateway(Protocol):
    """业务代码依赖的模型网关契约（异步版）。"""

    async def chat(self, user_text: str) -> ChatResult: ...

    def stream_chat(self, user_text: str) -> AsyncIterator[str]: ...
```

注意 `stream_chat` 的写法：`async def` + `yield` 的函数是**异步生成器函数**，签名标注为返回 `AsyncIterator[str]`，方法本身没有 `async` 修饰（`def stream_chat(...) -> AsyncIterator[str]`，内部用 `yield`）。

### 4.2 网关实现

`gateway.py` 整体替换。得益于第 2 章的客户端注入重构，迁移只触碰三处：构造点换 `AsyncOpenAI`、`await` 请求、流式改异步迭代：

```python
from __future__ import annotations

from collections.abc import AsyncIterator
from typing import Protocol

from openai import AsyncOpenAI

from agent_service.config import LLMSettings
from agent_service.schemas import ChatResult

SYSTEM_PROMPT = "你是设备维护知识助手。信息不足时明确说明，不编造事实。"


def _build_client(settings: LLMSettings) -> AsyncOpenAI:
    """全项目唯一的 SDK 客户端构造点。"""
    return AsyncOpenAI(
        api_key=settings.api_key,
        base_url=settings.base_url,
        timeout=settings.timeout_seconds,
        # 重试由 ReliableInvoker 显式实现并记录；SDK 层保持关闭。
        max_retries=0,
    )


class ModelGateway(Protocol):
    async def chat(self, user_text: str) -> ChatResult: ...

    def stream_chat(self, user_text: str) -> AsyncIterator[str]: ...
```

两种 API 风格的实现，点击标签切换：

=== "Chat Completions"

    ```python
    class ChatCompletionsGateway:
        """基于 Chat Completions API 的异步网关。"""

        def __init__(self, settings: LLMSettings, client: AsyncOpenAI) -> None:
            self._settings = settings
            self._client = client

        async def chat(self, user_text: str) -> ChatResult:
            response = await self._client.chat.completions.create(
                model=self._settings.model,
                messages=[
                    {"role": "system", "content": SYSTEM_PROMPT},
                    {"role": "user", "content": user_text},
                ],
            )
            text = response.choices[0].message.content or ""
            usage = response.usage
            return ChatResult(
                text=text,
                provider=self._settings.provider,
                model=response.model,
                input_tokens=usage.prompt_tokens if usage else 0,
                output_tokens=usage.completion_tokens if usage else 0,
                request_id=getattr(response, "_request_id", None),
            )

        async def stream_chat(self, user_text: str) -> AsyncIterator[str]:
            stream = await self._client.chat.completions.create(
                model=self._settings.model,
                messages=[
                    {"role": "system", "content": SYSTEM_PROMPT},
                    {"role": "user", "content": user_text},
                ],
                stream=True,
            )
            async for chunk in stream:
                if not chunk.choices:
                    continue
                delta = chunk.choices[0].delta.content
                if delta:
                    yield delta
    ```

=== "Responses"

    ```python
    class ResponsesGateway:
        """基于 Responses API 的异步网关。"""

        def __init__(self, settings: LLMSettings, client: AsyncOpenAI) -> None:
            self._settings = settings
            self._client = client

        async def chat(self, user_text: str) -> ChatResult:

                model=self._settings.model,

            text = response.output_text or ""
            usage = response.usage
            return ChatResult(
                text=text,
                provider=self._settings.provider,
                model=response.model,
                input_tokens=usage.input_tokens if usage else 0,
                output_tokens=usage.output_tokens if usage else 0,
                request_id=getattr(response, "_request_id", None),
            )

        async def stream_chat(self, user_text: str) -> AsyncIterator[str]:
            stream = await self._client.responses.create(
                model=self._settings.model,
                instructions=SYSTEM_PROMPT,
                input=user_text,
                stream=True,
            )
            async for event in stream:
                if event.type == "response.output_text.delta":
    ```

### 4.3 错误翻译：网关只抛 GatewayError

供应商 SDK 的异常类型不应该泄漏到业务层。建立 `src/agent_service/errors.py`：

```python
from __future__ import annotations

from typing import Any


class GatewayError(RuntimeError):
    """模型网关边界错误的统一形态。业务代码只处理它。"""

    def __init__(
        self,
        *,
        code: str,
        message: str,
        retryable: bool,
        status_code: int | None = None,
    ) -> None:
        super().__init__(message)
        self.code = code
        self.retryable = retryable
        self.status_code = status_code


def classify_openai_error(exc: Exception) -> GatewayError:
    """把 SDK 异常翻译成稳定错误码，并判断是否值得重试。"""
    status = getattr(exc, "status_code", None)

    if status == 429:
        return GatewayError(
            code="GW_RATE_LIMITED",
            message="供应商限流，稍后可重试",
            retryable=True,
            status_code=429,
        )
    if status is not None and 500 <= status < 600:
        return GatewayError(
            code="GW_UPSTREAM_5XX",
            message="供应商服务暂时不可用",
            retryable=True,
            status_code=status,
        )
    if status is not None and 400 <= status < 500:
        return GatewayError(
            code="GW_INVALID_REQUEST",
            message="请求被供应商拒绝，重试不会改变结果",
            retryable=False,
            status_code=status,
        )
    if exc.__class__.__name__ in ("APITimeoutError", "APIConnectionError"):
        return GatewayError(
            code="GW_TIMEOUT",
            message="连接或读取超时",
            retryable=True,
        )
    return GatewayError(
        code="GW_UNKNOWN",
        message="未分类的网关错误",
        retryable=False,
    )
```

两个网关的 `chat` 用统一的包装（以 Chat Completions 为例，Responses 相同）：

```python
from openai import APIError

async def chat(self, user_text: str) -> ChatResult:
    try:
        response = await self._client.chat.completions.create(...)
    except APIError as exc:
        raise classify_openai_error(exc) from exc
    ...
```

错误分类表（本章的核心决策依据）：

| 错误 | code | retryable | 理由 |
| --- | --- | --- | --- |
| 429 限流 | `GW_RATE_LIMITED` | 是 | 等待后通常恢复 |
| 5xx | `GW_UPSTREAM_5XX` | 是 | 供应商侧瞬时故障 |
| 连接/读取超时 | `GW_TIMEOUT` | 是 | 网络瞬时问题 |
| 400 参数错误 | `GW_INVALID_REQUEST` | 否 | 请求本身错了，重试原样再错 |
| 401/403 鉴权 | `GW_INVALID_REQUEST` | 否 | 换 Key 才有用 |
| 其他 | `GW_UNKNOWN` | 否 | 保守起见不重试 |

第 1 章 §12 的诊断经验在这里被固化成代码：401 检查 Key、429 检查额度、超时检查网络——**人肉诊断顺序变成机器分类规则**。

## 5. 并发执行：TaskGroup

### 5.1 工具异步化

`tools.py` 的三个函数加 `async`，用 `asyncio.sleep` 模拟外部 I/O 延迟：

```python
import asyncio

async def get_alarm(payload: GetAlarmInput) -> ToolResult:
    await asyncio.sleep(0.2)  # 模拟查询告警数据库
    ...  # 过滤逻辑与第 2 章相同

async def search_manual(payload: SearchManualInput) -> ToolResult:
    await asyncio.sleep(0.3)  # 模拟检索
    ...
```

### 5.2 collect_context：一次诊断的并发骨架

```python
import asyncio

from agent_service.schemas import (
    GetAlarmInput,
    AlarmQuery,
    SearchManualInput,
)
from agent_service import tools


async def collect_context(equipment_id: str) -> tuple[ToolResult, ToolResult]:
    """并发拉取告警与手册片段，整体预算 3 秒。"""
    async with asyncio.timeout(3):
        async with asyncio.TaskGroup() as tg:
            alarm_task = tg.create_task(
                tools.get_alarm(
                    GetAlarmInput(query=AlarmQuery(equipment_id=equipment_id))
                )
            )
            manual_task = tg.create_task(
                tools.search_manual(
                    SearchManualInput(equipment_id=equipment_id, keywords=["排查"])
                )
            )
    return alarm_task.result(), manual_task.result()
```

三个要点：

- **`TaskGroup` 中一个任务异常，同组其余任务立即被取消**。查告警失败时不再白等手册查询——错误尽快暴露，资源尽快释放；
- `asyncio.timeout(3)` 包住整组，是**总预算**：哪怕每个工具各自的超时都是 2 秒，两个 1.8 秒的慢查询加起来也不能突破 3 秒；
- 返回 `ToolResult` 信封而不是抛异常，是“工具层用信封表达业务失败”的选择；工具内部崩溃（如代码 bug）仍会以异常形式触发组取消。两种失败通道分工明确。

串行与并发的耗时对比（用 `time.monotonic` 自行验证）：串行 0.2 + 0.3 = 0.5 秒；并发约 0.3 秒——等于最慢的那个。

### 5.3 并发上限：Semaphore

并发不是越大越好：供应商有速率限制，数据库有连接池上限。`ReliableInvoker` 内部用 `asyncio.Semaphore` 限制同时在途的模型调用数：

```python
self._semaphore = asyncio.Semaphore(max_concurrency)  # 例如 4

async with self._semaphore:
    return await gateway.chat(user_text)
```

超过上限的请求在信号量上排队，而不是同时砸向供应商触发 429。第 8 周框架化之后，这层会演进为限流中间件，原理不变。

## 6. ReliableInvoker：可靠执行器

现在把超时、重试、退避、并发、取消、耗时组装成一个构件。创建 `src/agent_service/executor.py`：

```python
from __future__ import annotations

import asyncio
import random
import time
from dataclasses import dataclass

from agent_service.errors import GatewayError
from agent_service.schemas import ChatResult


@dataclass(frozen=True, slots=True)
class InvokeStats:
    """一次调用的执行观测数据。"""

    attempts: int
    elapsed_ms: int
    retried: bool
    error_code: str | None


@dataclass(frozen=True, slots=True)
class InvokeOutcome:
    result: ChatResult
    stats: InvokeStats


class ReliableInvoker:
    """模型调用的可靠执行器：超时 + 有限重试 + 退避 + 并发上限。"""

    def __init__(
        self,
        *,
        timeout_seconds: float = 30.0,
        max_retries: int = 2,
        base_delay: float = 0.4,
        max_concurrency: int = 4,
    ) -> None:
        self._timeout_seconds = timeout_seconds
        self._max_retries = max_retries
        self._base_delay = base_delay
        self._semaphore = asyncio.Semaphore(max_concurrency)

    async def chat(self, gateway, user_text: str) -> InvokeOutcome:
        started = time.monotonic()
        attempts = 0
        last_code: str | None = None

        async with asyncio.timeout(self._timeout_seconds):
            for attempt in range(self._max_retries + 1):
                attempts += 1
                try:
                    async with self._semaphore:
                        result = await gateway.chat(user_text)
                    stats = InvokeStats(
                        attempts=attempts,
                        elapsed_ms=int((time.monotonic() - started) * 1000),
                        retried=attempts > 1,
                        error_code=None,
                    )
                    return InvokeOutcome(result=result, stats=stats)
                except GatewayError as exc:
                    last_code = exc.code
                    if not exc.retryable or attempt == self._max_retries:
                        raise
                    await asyncio.sleep(self._backoff(attempt))

        raise GatewayError(  # pragma: no cover - 理论上不可达
            code="GW_UNREACHABLE", message="不可达", retryable=False
        )

    def _backoff(self, attempt: int) -> float:
        """指数退避 + 随机抖动：0.4 * 2^n * [0.5, 1.0)。"""
        delay = self._base_delay * (2 ** attempt)
        return delay * (0.5 + random.random() / 2)
```

逐个设计决策：

**总超时在外层。**`asyncio.timeout` 包住整个重试循环：第一次尝试 10 秒 + 退避 1 秒 + 第二次尝试 10 秒，总预算仍然是 30 秒，超时立即放弃。否则“每次 30 秒 × 3 次尝试”的最坏情况是 90 秒，调用方早已放弃。

**重试只针对 `retryable=True`。**第 5 节的错误分类表在这里生效：429 等 0.4~0.8 秒再试，5xx 再试；400 直接抛出，一次都不浪费。

**指数退避加抖动。**固定间隔重试的致命问题是“惊群”：100 个请求同时 429，同时醒来再砸一次。抖动把唤醒时间打散。退避序列示例（base=0.4）：第一次重试前等待 0.2~0.4 秒，第二次 0.4~0.8 秒。

**最多重试两次。**`max_retries=2` 意味着最多 3 次尝试。无上限重试 = 费用黑洞 + 故障放大器。

**`CancelledError` 不在捕获列表里。**`except GatewayError` 只捕获我们自己定义的错误。用户取消触发的 `CancelledError` 会穿过 `chat` 直接向外传播——这正是想要的。下一节展开。

**观测数据随结果返回。**`InvokeOutcome` 把 `attempts/retried/elapsed_ms/error_code` 带给调用方。第 5 章接上结构化日志后，“重试了多少次、为什么重试”就是一行日志的事。这也是“可解释 Baseline”的延续：第 1 章关闭 SDK 重试是为了看清真实失败；现在重试回来了，但每次都有记录。

## 7. 取消传播

### 7.1 CancelledError 是控制流，不是故障

```python
async def worker(gateway) -> None:
    try:
        await gateway.chat("...")
    except asyncio.CancelledError:
        print("任务被取消，清理中")
        raise  # 必须重新抛出
    finally:
        await release_resources()
```

三条铁律：

1. **捕获后必须重新抛出**。吞掉 `CancelledError` 的任务会“假装完成”，调用方拿到的是残缺状态；
2. 清理放 `finally`，别放 `except CancelledError` 里做完就不抛了；
3. 取消要传播到上游：任务取消 → 网关调用取消 → 底层 HTTP 连接断开。`AsyncOpenAI` 基于 httpx，任务取消时请求会被真正中断，不再计费。

### 7.2 验证取消真的生效

```python
async def main() -> None:
    task = asyncio.create_task(long_running_call())
    await asyncio.sleep(0.1)
    task.cancel()
    try:
        await task
    except asyncio.CancelledError:
        print("已确认取消")
```

对应的测试在 §9.4。Agent 场景里“用户关闭页面”最终就是这条链路：第 4 章的 SSE 接口会依赖它把上游调用停掉。

## 8. FlakyGateway：故障注入

`fakes.py` 增加一个按脚本出错的替身，覆盖本章全部故障场景：

```python
from __future__ import annotations

import asyncio
from collections.abc import AsyncIterator

from agent_service.errors import GatewayError
from agent_service.schemas import ChatResult


class FlakyGateway:
    """按脚本依次执行行为的故障注入替身。

    behaviors 每项取值：
    - "ok"：返回正常 ChatResult
    - "429"：抛可重试限流错误
    - "timeout"：抛可重试超时错误
    - "bad_request"：抛不可重试请求错误
    - "hang"：挂起 10 秒（用于触发总超时）
    - "cancelled"：抛 CancelledError
    """

    def __init__(self, behaviors: list[str]) -> None:
        self._behaviors = list(behaviors)
        self._index = 0
        self.chat_calls: list[str] = []

    async def chat(self, user_text: str) -> ChatResult:
        self.chat_calls.append(user_text)
        behavior = self._behaviors[min(self._index, len(self._behaviors) - 1)]
        self._index += 1

        if behavior == "ok":
            return ChatResult(
                text="Fake 恢复后的回复",
                provider="fake",
                model="fake-model",
                input_tokens=len(user_text),
                output_tokens=8,
                request_id=None,
            )
        if behavior == "429":
            raise GatewayError(
                code="GW_RATE_LIMITED", message="模拟限流", retryable=True, status_code=429
            )
        if behavior == "timeout":
            raise GatewayError(
                code="GW_TIMEOUT", message="模拟超时", retryable=True
            )
        if behavior == "bad_request":
            raise GatewayError(
                code="GW_INVALID_REQUEST", message="模拟永久错误", retryable=False, status_code=400
            )
        if behavior == "hang":
            await asyncio.sleep(10)
            raise AssertionError("不应到达这里")
        if behavior == "cancelled":
            raise asyncio.CancelledError()
        raise ValueError(f"未知行为: {behavior}")

    async def stream_chat(self, user_text: str) -> AsyncIterator[str]:
        yield "Fake 流式"
```

```python
import asyncio

import pytest

from agent_service.errors import GatewayError
from agent_service.executor import ReliableInvoker
from agent_service.fakes import FlakyGateway


async def test_retry_then_success() -> None:
    """429 后重试一次成功：attempts=2，retried=True。"""

async def test_permanent_error_no_retry() -> None:

        await invoker.chat(gateway, "问题")

    assert captured.value.retryable is False
    assert len(gateway.chat_calls) == 1


async def test_exhausted_retries() -> None:
    """持续 429：3 次尝试后放弃。"""
    gateway = FlakyGateway(["429", "429", "429"])
    invoker = ReliableInvoker(base_delay=0.01)

    with pytest.raises(GatewayError):
        await invoker.chat(gateway, "问题")

    assert len(gateway.chat_calls) == 3


async def test_total_deadline_enforced() -> None:
    """挂起行为被总超时截断。"""
    gateway = FlakyGateway(["hang"])
    invoker = ReliableInvoker(timeout_seconds=0.2, base_delay=0.01)

    with pytest.raises((TimeoutError, GatewayError)):
        await invoker.chat(gateway, "问题")


async def test_cancellation_propagates() -> None:
    """外部取消穿过执行器，不被吞掉。"""
    gateway = FlakyGateway(["hang"])
    invoker = ReliableInvoker(timeout_seconds=30.0)

    task = asyncio.create_task(invoker.chat(gateway, "问题"))
    await asyncio.sleep(0.05)
    task.cancel()

    with pytest.raises(asyncio.CancelledError):
        await task


async def test_concurrency_cap() -> None:
    """并发上限：峰值同时执行数不超过 max_concurrency。"""
    active = 0
    peak = 0

    class CountingGateway(FlakyGateway):
        async def chat(self, user_text: str) -> object:
            nonlocal active, peak
            active += 1
            peak = max(peak, active)
            try:
                await asyncio.sleep(0.05)
                return await super().chat(user_text)
            finally:
                active -= 1

    gateway = CountingGateway(["ok"] * 8)
    invoker = ReliableInvoker(max_concurrency=2, base_delay=0.01)

    outcomes = await asyncio.gather(
        *[invoker.chat(gateway, f"问题{i}") for i in range(8)]
    )

    assert peak <= 2
    assert len(outcomes) == 8
```

注意两个 pytest 配置：测试函数直接写 `async def` 需要异步支持（`uv add --dev pytest-asyncio`，并在 `pyproject.toml` 配置 `asyncio_mode = "auto"`）。另外测试里的退避基线压到 0.01 秒——真实退避值是给生产用的，测试关心的是行为顺序而不是真实等待时间。

## 11. 常见错误与诊断顺序

### 11.1 RuntimeError: coroutine was never awaited

漏了 `await`，或把协程当普通函数返回值传递。诊断：看堆栈里协程创建的位置，补 `await`。

### 11.2 事件循环卡死

现象：所有请求同时变慢。按顺序排查：是否在协程里调用了同步阻塞库（同步 SDK、`time.sleep`、`requests`）；是否有一个 CPU 密集循环占住了循环。解法分别是换异步客户端、`await asyncio.sleep`、`asyncio.to_thread` 隔离。

### 11.3 重试后 429 更严重

退避没有抖动（惊群），或并发上限过高。检查 `_backoff` 实现和信号量上限。

### 11.4 TimeoutError 与 GatewayError 混淆

`asyncio.timeout` 抛的是内置 `TimeoutError`（3.11 起 `asyncio.TimeoutError` 是它的别名）。若希望统一走 `GatewayError` 通道，捕获后转换；测试里两者都接受（见 `test_total_deadline_enforced`）。

### 11.5 pytest-asyncio 不执行异步测试

`asyncio_mode = "auto"` 没配置时，异步测试会被静默跳过或报 warning。确认 `pyproject.toml` 里的配置，或用 `@pytest.mark.asyncio` 显式标记。

## 12. 练习题与答案

### 练习 1：为什么所有异常都重试反而更不稳定？

**答案：**永久错误不会恢复，重试只是把同样的失败再买几次单；流量被放大后，原本正常的请求也被拖慢；非幂等写操作可能重复执行（重复建单、重复扣款）。重试的前提是“错误是瞬时的”且“重放是安全的”。

### 练习 2：客户端断开后模型调用是否继续？

**答案：**普通问答应该取消——没人消费结果，继续执行只是烧钱。但已经进入业务事务的操作（比如工单已创建到一半）要按业务语义决定完成或补偿，不能只看连接状态。这就是“取消传播”与“幂等键”配合的原因。

### 练习 3：为什么 `except Exception` 会破坏取消机制？

**答案：**`asyncio.CancelledError` 在 3.8+ 继承自 `BaseException`，`except Exception` 不会捕获它——但 `except BaseException` 或裸 `except:` 会。捕获后不重新抛出，任务就无法真正停止，上层 `await task` 会永远等不到结束信号。

### 练习 4：`max_retries=2` 与“最多调用 3 次”是什么关系？

**答案：**同一件事的两种说法：1 次原始尝试 + 2 次重试 = 3 次尝试。面试和文档里要统一口径，避免“重试 3 次”被理解成 4 次尝试。

### 练习 5：重试对写工具意味着什么？

**答案：**读操作重放无害；写操作必须幂等——调用方带 `idempotency_key`（第 2 章已在契约里预留），执行方识别重复请求返回首次结果。没有幂等键的写操作，宁可不重试。

## 14. 面试追问

### 14.1 说说你对 asyncio 事件循环的理解

回答框架：单线程协作式调度；协程在 `await` 处让出控制权；循环基于就绪回调驱动；阻塞调用会冻结整个循环。加分项：说出 GIL 与协程的关系（协程解决 I/O 并发，GIL 限制的是计算并行），以及 `asyncio.to_thread` 的适用位置。

### 14.2 重试策略怎么设计？

回答框架：错误分类先行（瞬时/永久）→ 有限次数 → 指数退避加抖动 → 总超时预算罩住全部尝试 → 每次重试可观测 → 写操作幂等。能主动说出“无脑重试放大故障”的，是真正理解的人。

### 14.3 TaskGroup 相比 gather 的优势？

回答框架：结构化并发——任务组内的生命周期被限定在 `async with` 块内，一处异常自动取消全组且等待清理完成；`gather` 的异常默认不传播（`return_exceptions` 语义易错），泄漏任务的风险更高。
