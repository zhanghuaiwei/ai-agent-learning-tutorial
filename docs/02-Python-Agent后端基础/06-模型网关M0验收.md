# 模型网关 M0 验收

> 第 2 周里程碑｜目标：建立后续章节复用的可靠底座。

## 1. 必交功能

- 统一 `ChatModel` 接口，千问与 DeepSeek 仅存在于 Provider Adapter。
- 普通与 SSE API；请求、运行、费用 ID 可关联。
- 超时、限次重试、并发限制、取消、错误映射。
- Fake Model 与回放；不联网能跑 CI。
- `.env.example`、结构化日志、费用台账、启动说明。

## 2. 验收场景

| 场景 | 预期 |
|---|---|
| 正常问答 | 返回模型、Token、估算费用 |
| 首次 429 后成功 | 仅重试一次并记录原因 |
| 永久 401 | 不重试，安全错误信息 |
| 总超时 | 规定时间结束，无遗留任务 |
| 客户端断开 | 可取消的上游任务被取消 |
| 费用异常增长 | 告警并定位循环、重试或上下文异常，不按教程金额自动停用 |
| 流中途失败 | 发送 `run.failed` |

## 3. 练习与答案

### 练习 1：为何不直接到处调用供应商 SDK？

**答案：**网关隔离供应商差异，集中处理超时、执行边界、费用观测和脱敏，让业务可测试、模型可替换；只抽象实际共同能力。

### 练习 2：怎样证明切 Provider 没破坏业务？

**答案：**运行契约测试、固定评测集和少量影子流量，对比结构正确率、成功率、延迟、成本与安全指标。

## 4. 通过标准

不少于 20 个测试；连续 30 次 Fake 请求无泄漏；真实调用费用可查；能脱稿解释异步、重试和评测。未通过先补底座，不进入框架章节。
