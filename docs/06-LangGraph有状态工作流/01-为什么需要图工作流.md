# 为什么需要图工作流

> 预计 4 小时｜目标：从“聊天循环”升级到可恢复的企业业务流程。

## 1. 单 Agent 的边界

工单协同包含检索、诊断、风险分级、生成草稿、人工确认、提交、通知和失败补偿。若全部藏在一次 Agent Loop 中，状态、审批点、重试范围和副作用难以验证。

Graph 把流程表示为 State、Node 和 Edge：节点执行有限职责，边决定下一步，Checkpointer 保存状态。模型可在局部提供判断，但业务边界由图固定。

## 2. 何时用 LangGraph

- 任务跨多个请求或等待人工数小时。
- 中途失败后需要从检查点继续。
- 有明确状态、并行分支、条件路由或审批。
- 需要审计每次状态转移与重放。

一次简单问答不必上 Graph。图不是为了画得复杂，而是显式管理长期运行和不确定性。

## 3. 项目任务

把工单流程画为：接收 → 获取上下文 → 检索 → 诊断 → 风险判断 → 草稿 → 等待确认 → 提交 → 完成；标出模型节点、确定性节点、副作用和失败终态。

## 4. 练习与答案

### 练习 1：所有节点都调用 LLM 合理吗？

**答案：**不合理。校验、权限、状态转移、幂等提交等确定性逻辑应用代码实现，模型只处理语义不确定部分。

### 练习 2：Graph 与微服务是一回事吗？

**答案：**不是。Graph 是一次业务运行的编排模型；节点可在同一进程，也可调用外部服务。服务边界由数据所有权和团队边界决定。

## 5. 验收与资料
