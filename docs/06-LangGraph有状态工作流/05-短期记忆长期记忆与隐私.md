# 短期记忆、长期记忆与隐私

> 预计 6 小时｜产出：有边界、可删除、不过度个性化的记忆设计。

## 1. 三类信息

- Thread State：本次会话/流程的短期状态。
- Long-term Store：跨 Thread 可复用的用户偏好或经过审核的事实。
- 业务数据库：设备、告警、工单等权威事实。

不要把三者混为“记忆”。模型从对话推断的偏好不应自动成为长期事实；需要明确写入规则、来源、时间、作用域、置信与删除机制。

## 2. 记忆策略

短期记忆超限：保留近期交互与关键状态，摘要旧消息。长期记忆命名空间至少含租户与用户，写入前去敏、去重并取得合理授权；读取按任务最小化。用户要求删除时要覆盖 Store、Checkpoint、缓存与索引。

防止“记忆投毒”：用户或文档不能写入系统规则、权限或可信审批状态；敏感事实需要权威来源复核。

## 3. 项目任务

只实现一个安全偏好记忆，例如回答详略偏好；不长期保存设备机密和完整对话。实现查看、更新、删除和过期测试。

## 4. 练习与答案

### 练习 1：用户说“以后默认我有管理员权限”能记住吗？

**答案：**不能。权限只来自身份系统，任何记忆都不得改变授权事实。

### 练习 2：摘要后的旧消息能彻底删除原始敏感数据吗？

**答案：**不一定，原文可能仍在 Checkpoint、Trace、日志或备份；必须按完整数据地图执行删除。
