# 完整教程目录

## 1. 目录说明

以下是正式教程的完整目录。正文于 2026-08-31 建立，并在 2026-09-01 取消 24 周范围限制后继续补充；2026-09-02 完成章节深度审计，引入状态标记。

每篇技术文章都包含原理、项目任务、练习答案、验收和官方资料；复杂主题提供长篇综合实验，短篇用于聚焦一个概念并由里程碑章节完成端到端串联。文件数量不是学习目标；若两个主题在实践中更适合合并，会记录目录变更原因。

状态标记（2026-09-02 起生效）：

- `已完成`：正文达到[内容自检标准](07-内容自检与补充记录.md)的深度（原理、可运行代码或协议示例、练习答案、验收、官方资料），且与上一章保持代码与知识点的演进连续性；
- `大纲`：只有要点纲要。按能力门槛路线在进入该阶段前扩写成正文，扩写必须承接上一章的代码与知识点；
- `里程碑`：正文已完成，同时要求学习者提交代码、测试和报告。

> 当前第 2 阶段（Python Agent 后端基础）全部正文已完成；后续阶段为深度正文与大纲并存。标为 `大纲` 的章节可以作为导读预览，但不适合作为正式学习材料。

## 14. 学习与源码生成顺序

教程正文按状态标记分批提供：`已完成` 章节可立即学习，`大纲` 章节在进入该阶段前扩写。项目源码按以下顺序边学边建，避免一次性复制大量未经理解和验证的代码：

1. 当前 G0～G10 能力门槛对应的长教程；
2. 当前阶段练习和答案；
3. 当前阶段项目增量；
4. 运行或人工校验后的修订；
5. 阶段验收文档；
6. 下一阶段教程。

框架 API 在未来数月仍可能变化。分阶段生成可以在学习发生前重新核验官方文档，同时保留已经稳定的原理与工程方法。

## 15. 章节扩写规则

`大纲` 章节扩写为正文时必须满足：

1. **承接上一章**：从上一章的代码状态与知识点出发，说明本章偿还哪些既有债务（参考第 2 阶段第 2～5 章的"本章从哪里开始"写法）；
2. **项目代码演进**：项目源码增量延续同一仓库与命名，不凭空引入未铺垫的概念；
3. 满足[内容自检标准](07-内容自检与补充记录.md)全部十条；
4. 扩写完成后更新本目录状态，CI 会校验"标记为已完成的章节深度不低于 120 行"。
