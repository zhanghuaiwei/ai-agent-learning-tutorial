# 教程内容自检与补充记录

> 最近自检：2026-08-31｜用途：让教程的“完整”可以被检查，而不是只由文件数量证明。

## 1. 自检标准

每篇核心技术教程至少满足：

1. 学习目标和预计投入明确；
2. 解释核心心智模型与适用边界；
3. 提供可运行代码、协议示例或足够具体的伪代码；
4. 说明至少一个失败路径、安全边界或版本陷阱；
5. 能并入“智维 Agent”主项目；
6. 至少两道练习并紧跟答案；
7. 有可验证的验收标准；
8. 有对应官方资料；
9. 框架 API 标明版本基线，不混用旧接口；
10. 不把 Prompt、框架默认值或“模型自觉”当作企业安全与可靠性保证。

教程整体还要满足：阶段里程碑一致、24 周总时间可执行、前端内容不重复、Python Agent 主线不被 Java 增强线打断、本地无 Docker/本地模型也能学习。

## 4. 版本核验结论

本轮按 2026-08-31 官方资料核验以下内容：

- LangChain 使用 1.x `create_agent`，Structured Output 使用 `ProviderStrategy/ToolStrategy`；Runtime Context 通过 `context_schema` 注入。
- LangChain Streaming 包含 `updates/messages/custom`；v2 统一格式要求锁定支持该功能的 LangGraph 版本。
- LangGraph 持久化围绕 Checkpoint、Thread、Pending Writes；Interrupt 恢复使用 `Command(resume=...)`。
- LangGraph 动态 Map-Reduce 使用 `Send`，并行分支属于 Super-step，更新顺序不能当业务排序。
- MCP 正式学习基线固定为 2025-11-25；远程标准 Transport 是 Streamable HTTP，旧 HTTP+SSE 只作为兼容知识。
- MCP HTTP Authorization 基于 OAuth 体系、Protected Resource Metadata 和目标 Resource/Audience 绑定；stdio 不照搬 HTTP OAuth 流程。
- SQLAlchemy 使用 2.x `select()` 与每并发 Task 独立 `AsyncSession`；Schema 变更由 Alembic Migration 管理。
- OpenTelemetry Python 的 Trace 与 Metric 可用于课程生产观测；Logs 的成熟度和具体 Exporter 仍以进入该阶段时的官方状态为准。

## 5. 进入每个阶段前的二次检查

框架和模型会继续更新，因此“本轮通过”不等于以后无需复核。进入 LangChain、LangGraph、MCP 阶段的第一天执行：

```text
1. 查看 uv.lock 中真实版本
2. 打开对应官方 Versioning/Migration/Specification
3. 跑该模块最小导入与 Smoke Test
4. 核对教程代码签名
5. 更新版本矩阵和 ADR
6. 跑上一里程碑回归
```

API 发生变化时优先修改 Adapter 和教程示例，不改变稳定的业务边界、评测数据与外部 SSE/API 契约。

## 6. 学习者自检题与答案

### 自检 1：一篇教程有概念、练习和官方链接，但没有可运行产出，算完成吗？

**答案：**不算。至少要能用代码、测试、协议样例或评测结果证明理解，并并入主项目。

### 自检 2：官方文档中的 Demo 可以直接视为企业架构吗？

**答案：**不能。Demo 用于说明 API；身份、租户、幂等、事务、数据保留、错误契约、可观测性和部署由应用架构补齐。

### 自检 3：为什么教程还要在进入阶段前复核版本？

**答案：**LangChain、LangGraph、MCP 和模型能力变化快。长期教程应固定稳定概念和验证方法，代码签名则以锁定版本及对应官方文档为准。
