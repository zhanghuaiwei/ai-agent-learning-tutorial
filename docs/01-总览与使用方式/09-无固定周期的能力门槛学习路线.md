# 无固定周期的能力门槛学习路线

> 本文是课程的默认学习路线。原 `24 周学习计划` 保留为压缩排期参考，不再决定教程范围，也不能用“周数已到”代替能力验收。

## 1. 为什么从周计划改为能力门槛

固定周数适合安排日历，却容易制造三种错觉：

1. 看完一周的材料就等于掌握；
2. 为赶进度跳过失败复盘、测试和重构；
3. 岗位新出现的能力因为“不在 24 周内”而被永久删掉。

本课程改用以下闭环：

```text
诊断当前能力
  → 学习稳定原理
  → 完成最小练习
  → 并入企业项目
  → 故障/安全/评测验证
  → 形成可审查证据
  → 通过门槛后进入下一阶段
```

时间仍要记录，但时间只是投入，不是完成定义。每个门槛可以第一次不通过；修复后重新验收，比在简历上堆框架名更有价值。

## 2. 三条路线同时存在

### 2.1 求职核心线

面向 AI Agent 应用开发工程师、AI 应用后端工程师。必须在正式投递前完成 G0～G8，重点是 Python 后端、RAG、LangChain、LangGraph、评测、安全、业务集成和上线证据。

### 2.2 岗位适配线

G9 根据目标 JD 选做。它包括 Dify、LlamaIndex、AutoGen、Semantic Kernel、AgentScope/ADK、A2A、Agent Skills、Text2SQL、多模态和 Agent 平台运行时。目标不是精通所有框架，而是证明能把已有原理迁移到陌生技术栈。

### 2.3 长期进阶线

G10 面向入职后的五年成长：开源贡献、云原生、模型服务、轻量微调、复杂评测、领域数据治理和技术负责人能力。它不阻塞应用开发岗位投递，但不能被教程范围永久排除。

## 3. 阶段门槛总览

| 门槛 | 能力主题 | 必交证据 | 失败时回退 |
| --- | --- | --- | --- |
| G0 | 基线与工程环境 | 可重建环境、Git 记录、模型网关 | Python、HTTP、Git 补缺 |
| G1 | 原生 LLM 与 Agent | 手写 Agent Loop、工具契约、停止条件 | Structured Output/Tool Calling |
| G2 | LangChain 单 Agent | 可测试单 Agent、流式事件、Middleware | 原生机制和框架抽象对照 |
| G3 | 企业 RAG | 摄取、混合检索、引用、拒答、分层评测 | 数据清洗/检索指标单独重做 |
| G4 | LangGraph 工作流 | 持久化、审批、恢复、幂等副作用 | 状态机、事务与执行语义 |
| G5 | 评测与可观测性 | 数据集、实验报告、Trace、回归门禁 | 指标定义和标注一致性 |
| G6 | 安全与协议 | MCP、认证、租户隔离、红队用例 | 威胁模型和最小权限 |
| G7 | 生产工程 | DB/Queue、SLO、负载、CI、部署与 Runbook | 后端或可靠性专项补缺 |
| G8 | 企业项目与面试 | Release Candidate、证据矩阵、模拟面试 | 按薄弱证据回到对应阶段 |
| G9 | 岗位适配专题 | 两个以上可运行对照实验 | 只选目标 JD 高频项 |
| G10 | 长期进阶 | 开源贡献或平台/模型专项报告 | 重新确定职业分支 |

## 4. G0：从“会语法”到能维护 Python 服务

必须证明：

- 能使用类型提示、Pydantic、Protocol 和异常体系表达契约；
- 能解释协程、线程和进程的差异，并正确使用超时、取消与并发上限；
- 能设计 REST/SSE 接口，写单元测试、集成测试和结构化日志；
- 能使用 SQL 完成连接、聚合、事务和索引分析；
- 能从空目录按 README 重建环境。

必交物：

```text
apps/agent_api/
tests/
pyproject.toml
uv.lock
.env.example
README.md
docs/error-contract.md
```

通过条件：测试可重复，Secret 未入库，模拟模型时 CI 不访问外网；面对 429、超时、客户端断线能够说明系统终态。

## 5. G1：不依赖框架理解 Agent

必须亲手实现一次：

1. 输入消息和系统约束；
2. 模型生成结构化工具请求；
3. 工具参数验证和授权；
4. 工具执行与规范化结果；
5. 结果回填模型；
6. 完成、拒绝、超时、最大步数和人工审批终止。

面试时应能在白板上解释：为什么 Tool Schema 不是权限、为什么模型输出永远不可信、为什么副作用工具不能盲目重试、ReAct 与 Plan-and-Execute 的适用差异。

通过条件：至少包含 20 条工具选择用例、5 条越权用例、3 种失败终态，并能从 Trace 还原每一步。

## 6. G2：LangChain 不是背 API

学习目标分为三层：

- 稳定抽象：Model、Message、Tool、Middleware、Runtime Context；
- 当前实现：`create_agent`、Structured Response、流式事件；
- 框架边界：何时直接写函数、何时使用 LangGraph、何时不用 Agent。

必须保留“原生 Agent 与 LangChain Agent 的对照表”，包含代码量、可测试性、事件模型、扩展点、版本耦合和故障定位。

通过条件：切换千问/DeepSeek Adapter 不修改业务层；Tool 错误不会变成伪造成功；敏感日志经过脱敏；框架升级由契约测试保护。

## 7. G3：把 RAG 当数据系统

RAG 不能只演示“上传 PDF 后能聊天”。必须覆盖：

- 文档来源、ACL、版本、删除和增量更新；
- OCR/表格/标题层级和解析失败；
- Chunk 策略、元数据、Embedding 版本和索引重建；
- Dense、BM25、过滤、RRF、Rerank；
- 引用、证据冲突、过期内容和拒答；
- Recall@K、MRR/NDCG、引用正确性、忠实度与业务任务成功率；
- 文档 Prompt Injection 和跨租户泄漏测试。

通过条件：数据集至少包含可回答、不可回答、冲突、过期、权限隔离和注入样本；任何优化必须给出基线、候选、误差案例和成本/延迟变化。

## 8. G4：LangGraph 与持久化业务流程

必须完成一个跨请求工作流：

```text
接收告警
  → 检索证据
  → 生成诊断草稿
  → 风险判定
  → 人工批准/编辑/拒绝
  → 幂等创建工单
  → 记录完成或补偿
```

验收必须覆盖：进程在任一节点崩溃、批准等待一天后恢复、相同请求重复提交、旧 Graph 版本恢复、工具超时结果未知、并行节点合并冲突。

通过条件：状态中不保存无法序列化对象；节点重放不会重复产生业务副作用；每个终态可解释、可查询、可告警。

## 9. G5：建立平台无关的评测能力

LangSmith 是主工具，但能力不能被产品界面绑定。统一评测记录至少包含：

```json
{
  "case_id": "incident-017",
  "dataset_version": "v3",
  "app_version": "git-sha",
  "prompt_version": "diagnosis-v5",
  "model": "provider/model",
  "inputs": {},
  "outputs": {},
  "trajectory": [],
  "scores": {},
  "latency_ms": 0,
  "usage": {},
  "error": null
}
```

必须区分确定性断言、人工标注、LLM Judge、成对比较和线上业务信号。安全不以平均分表示：越权、高风险误执行等采用零容忍门禁。

通过条件：同一数据可以在本地 JSONL/pytest 和 LangSmith 上运行；候选版本未通过门禁时 CI 失败；Judge 至少用人工样本做过校准。

## 10. G6：协议与安全边界

必须实现：

- 一个只读 MCP Server；
- 一个需要 OAuth/Scope 的远程工具；
- Prompt Injection、Tool Poisoning、SSRF、跨租户、Secret 泄漏负向用例；
- 高风险操作的预览、审批、幂等和审计；
- Tool、Resource、Agent、User 四类身份与权限边界。

A2A 与 Agent Skills 在 G9 深入，本阶段只需理解它们不能替代认证、授权和业务校验。

通过条件：默认拒绝；用户文本不能扩大权限；远端返回、检索内容和其他 Agent 消息一律按不可信输入处理。

## 11. G7：从 Demo 到生产服务

必须完成以下故障实验：

1. 模型 429、5xx、慢响应和返回格式漂移；
2. Redis/数据库短暂不可用；
3. Worker 处理后、ACK 前崩溃；
4. SSE 经代理缓冲或客户端断开；
5. 队列积压、重试风暴和死信增长；
6. 部署新版本后旧 Thread 恢复失败；
7. 单租户异常流量挤压其他租户；
8. 成本或 Tool Loop 异常增长。

通过条件：每个实验都有可观察信号、自动或人工处置、数据一致性结论和 Runbook；不是只写“增加重试”。

## 12. G8：企业项目和面试证据

Release Candidate 至少包含：

- 需求说明、范围外声明和用户故事；
- C4 架构图、状态图、数据所有权和威胁模型；
- OpenAPI、事件契约、数据库迁移和权限矩阵；
- 单元/集成/E2E/评测/负载/安全报告；
- ADR、发布回滚、Runbook 和事故复盘；
- 一分钟、三分钟、八分钟项目表达；
- 至少两次完整系统设计和两次现场编码录像/记录；
- 简历中每条技术断言对应一个可打开的证据。

通过条件：陌生面试官能在 15 分钟内按 README 看到业务价值、运行路径、质量数据、失败案例和架构取舍。

## 13. G9：按 JD 选择专题，不再受周数限制

| 专题 | 触发条件 | 最小证据 |
| --- | --- | --- |
| LlamaIndex | JD 强调 RAG/数据框架 | 同数据集迁移摄取与检索并对比 |
| AutoGen/AgentScope/ADK | JD 强调多 Agent | 同一任务实现终止、状态、审批和 Trace |
| Semantic Kernel/Spring AI | Java/.NET 企业集成岗位 | Java 业务 Tool 或插件最小实验 |
| Dify/Coze | 交付/低代码平台岗位 | DSL、API、权限、版本迁移对照 |
| A2A/Agent Skills | Agent 平台/互操作岗位 | Agent Card/Task 或一个可移植 Skill |
| Text2SQL | 数据分析/工业/BI 岗位 | 只读、Schema 白名单、SQL AST 验证和执行评测 |
| 多模态 | 客服、文档、制造、内容岗位 | 图片/OCR/语音输入的受控处理链 |
| Agent Runtime | 平台/高级后端岗位 | 网关、队列、沙箱、租户配额和运行审计设计 |
| 模型服务/LoRA | JD 明确要求 | 云端小实验或可复现选型/容量报告 |

选择原则：目标 JD 连续采样中出现、与主项目能形成真实业务价值、能在投递前产生证据。不要因为教程没有时间上限就同时学习五个相似框架。

## 14. G10：长期进阶路线

完成主线后，从三条分支中选择一条深入：

### 应用架构师

重点：复杂业务建模、平台能力复用、多租户、合规、SLO、成本治理、跨团队交付。

### Agent 平台工程师

重点：LLM Gateway、插件/Skill 生命周期、调度与 Durable Execution、沙箱、策略控制面、Kubernetes 和开发者体验。

### 模型应用与算法交叉

重点：PyTorch/Hugging Face、数据构造、SFT/LoRA、推理服务、模型/RAG/Tool 联合评测。进入这条分支前先确认目标岗位的学历与算法要求。

每条分支都要求一个公开证据：开源 PR、技术报告、可复现实验或真实业务指标，而不是证书数量。

## 15. 学习节奏建议

每周 15 小时仍可作为资源预算：

| 活动 | 建议占比 | 说明 |
| --- | ---: | --- |
| 原理与官方文档 | 20% | 重点读概念、限制和版本说明 |
| 编码与项目增量 | 45% | 每次只完成可验收切片 |
| 测试、评测、故障实验 | 20% | 允许暴露失败，不追求演示美观 |
| 面试表达与基础题 | 10% | 与当前阶段同步训练 |
| JD 复核和复盘 | 5% | 每月调整 G9 专题 |

如果某个门槛连续两次未通过，停止新增功能，建立最小失败样例并回到前置知识。若临近投递阶段，优先保证 G0～G8 的证据闭环，再按 JD 选择一个 G9 专题。

## 16. 练习与答案

### 练习 1：G3 花了三周仍未通过，是否应该先学 LangGraph？

**答案：**通常不应。若失败集中在文档质量、检索或评测，进入 LangGraph 只会把 RAG 缺陷包进更复杂的流程。先缩小到 20 条数据、一个 Retriever 和一个明确指标，完成错误归因后再继续。

### 练习 2：教程范围不受时间限制，是否应精通所有 Agent 框架？

**答案：**不需要。框架广度通过“同一业务迁移实验”证明，深度集中在原生机制、LangChain/LangGraph 和生产工程。只有目标 JD 明确要求时，才把某个框架升级为深入专题。

### 练习 3：如何判断一个阶段真的完成？

**答案：**看陌生人能否根据证据复现、是否包含失败用例、是否有定量门槛、能否回答取舍与边界。学习时长、文章阅读数和视频收藏数都不是完成证据。

### 练习 4：面试日期临近但 G9 尚未完成怎么办？

**答案：**先用目标 JD 判断是否影响硬门槛。应用开发岗位通常优先 G0～G8；从 G9 只选择出现率最高且能在短周期形成可信实验的一项。简历诚实写“理解”而不是“精通”。

## 17. 验收清单

- [ ] 为 G0～G10 建立证据目录和状态；
- [ ] 每个已通过门槛至少有代码、测试/评测和复盘三类证据；
- [ ] 24 周文件仅作为排期参考，不再作为课程完成标准；
- [ ] 每月用真实 JD 调整 G9，不随热点无边界扩张；
- [ ] 投递前完成 G0～G8 的最终复验；
- [ ] 为未掌握项使用准确表述，不夸大商业经验或生产规模。
