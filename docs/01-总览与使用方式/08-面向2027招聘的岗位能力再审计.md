# 面向 2027 招聘的岗位能力再审计

> 样本核验日期：2026-09-01｜目标：西安 AI Agent 应用开发工程师 / AI 应用开发工程师｜下一次强制复核：2026-11-01。

## 1. 为什么需要再次反推课程

“会 LangChain”不是岗位能力，它只是实现路径之一。招聘方真正购买的是：把不稳定的模型能力接入真实业务，并将其做成可交付、可排障、可评测、可迭代的系统。

这一轮不以技术热度决定课程，而采用以下证据链：

```text
当前 JD 职责与要求
  → 岗位族分类
  → 能力出现强度与淘汰风险
  → 教程章节
  → 项目产出
  → 简历证据
  → 面试追问与现场题
```

公开 JD 会过期、会被搜索引擎截断，也可能存在招聘平台转录误差。因此样本只用于发现共同能力，不用于推断岗位数量、薪资或录用概率；投递前必须重新采样。

### 2.1 高频共同项

按是否会直接影响简历筛选和技术面试，将能力重新分层。

**P0：2027-02 前必须能用项目证明**

1. Python：类型、异步、异常、测试、包管理、代码组织和基本性能分析；
2. FastAPI/REST/SSE：认证、错误契约、超时、并发、流式断线和接口测试；
3. LLM 应用基础：Prompt、Context、Structured Output、Function Calling、模型选型；
4. LangChain 与 LangGraph：能写、能调、能解释何时不用；
5. RAG：摄取、切分、向量/混合检索、重排、引用、拒答和分层评测；
6. Agent 工程：状态、记忆、审批、幂等、停止条件、任务恢复和权限；
7. 数据与中间件：SQL、事务、索引、Redis、后台任务/队列的交付语义；
8. MCP 与外部系统集成：工具协议、OAuth、Java/第三方 API 边界；
9. 生产质量：日志/指标/Trace、限流、降级、负载测试、安全和 CI；
10. 独立交付：需求澄清、技术方案、开发测试、上线检查、问题定位和文档。

**P1：目标 JD 出现时应能完成小实验或演示**

- Dify 工作流：能把同一业务分别映射到可视化节点和 LangGraph，并说明迁移边界；
- Docker/Kubernetes：能写构建和部署配置，理解 Pod/Deployment/Service/Probe，不要求本机维护集群；
- 模型部署：理解 vLLM 的 OpenAI-compatible 服务、并发/批处理/KV Cache/量化的关系；
- PyTorch/Hugging Face：能读懂张量、Tokenizer、Causal LM 和 PEFT 示例；
- 多模态/OCR：能把图片或扫描文档接入受控处理链，而不是训练视觉模型；
- Text2SQL：能完成 Schema 检索、AST 白名单、只读执行、租户隔离和执行评测；
- 框架迁移：能将统一 Tool/State/Eval 契约迁移到 LlamaIndex、AutoGen、Semantic Kernel、AgentScope/ADK 中的两个；
- A2A/Agent Skills：理解与 MCP/框架内多 Agent 的边界，并完成模拟任务和可移植 Skill；
- Agent Runtime：平台岗位需要理解 Release、Durable Task、LLM Gateway、Sandbox、Artifact 和租户配额；
- Spring AI：Java 企业岗位需要完成 ChatClient/Advisor/Tool/MCP 与 Python 主线的统一契约实验；
- 开源协作：至少完成一个高质量 Issue、文档 PR 或可复现 Bug 报告。

**P2：面试级理解，除非 JD 明确要求才深入**

- SFT/LoRA 数据生产和训练实操；
- vLLM/SGLang/TensorRT-LLM 性能调优；
- Kubernetes 调度器、GPU 集群和分布式训练；
- RLHF/DPO、预训练、CUDA 算子和模型结构研究；
- GraphRAG、多模态训练、复杂代码沙箱基础设施研发等垂直专题。

## 3. 三类岗位必须分开判断

### 3.1 AI 应用 / Agent 应用开发：本课程主投

典型职责是接模型、建 RAG/Agent、集成业务 API、交付后端服务、评测优化和上线排障。面试权重大致落在：项目深挖、Python 后端、Agent/RAG 原理、系统设计和业务取舍。

你现有四年前端经验可以证明软件交付、接口协作和用户体验，但不能自动证明 Python 后端深度。需要用项目中的异步、数据库、队列、权限、测试和故障复盘补足。

### 3.2 Agent 平台 / AI 平台工程：可投但需 JD 适配

除了应用能力，还会要求租户、配额、模型网关、工作流平台、插件生态、部署与可观测性。主项目完成后已具备基础，但遇到强 K8s、模型托管或平台控制面要求时，要降低匹配分而不是硬投。

### 3.3 大模型算法 / 推理 Infra：不是当前主线

这类岗位常要求研究生背景、PyTorch 深度、训练、量化、GPU、CUDA 或推理引擎。能解释 Transformer、LoRA、vLLM 并不等于具备算法/Infra 岗能力。不要在简历中把“调用云 API”写成“模型部署优化”。

## 5. 取消教程范围的 24 周上限

24 周计划保留为 2027 年投递窗口前的压缩排期，但不再承担课程目录和完成定义。默认采用 G0～G10 能力门槛：

| 层次 | 内容 | 投递关系 |
| --- | --- | --- |
| G0～G8 | Python、原生 Agent、LangChain、RAG、LangGraph、评测、安全、生产工程和企业交付 | 应用开发岗位投递前核心门槛 |
| G9 | 框架迁移、Dify、Text2SQL、多模态、A2A/Skills、Agent Runtime、模型服务 | 按目标 JD 选择，不受周数限制 |
| G10 | 开源、云原生、平台或模型交叉深入 | 长期五年发展路线 |

新增专题不是要求同时精通所有技术。先完成主线证据，再使用真实 JD 的出现频率、业务价值和硬门槛选择 G9。若时间接近面试，宁可诚实标注“理解/实验”，也不能削减 Python、RAG、LangGraph、数据库、队列、权限、评测和项目表达。

## 6. 面试胜任标准

“教程读完”不是胜任。投递前应同时满足：

- 给定一个业务问题，30 分钟内完成需求澄清、核心状态、工具与风险设计；
- 不查教程写出 FastAPI 接口、Pydantic Schema、异步 Tool 调用和错误映射；
- 从空库建立文档摄取、检索、引用和拒答的 RAG 最小闭环；
- 使用 LangGraph 实现持久化、Interrupt、恢复和幂等副作用；
- 解释 Redis 缓存与任务队列的不同，以及至少一次投递为何仍需幂等；
- 根据 Trace/Metric/Log 定位一个真实故障，而不是只会添加日志；
- 用测试和评测数据证明优化有效，并说明样本限制；
- 展示一个失败案例、一个架构取舍和一个上线回滚方案；
- 对陌生 JD 能诚实区分“已证明、理解、未掌握”。

## 7. 练习与答案

### 练习 1：JD 同时写 LangChain、Dify、微调、K8s，是否四项都要精通？

**答案：**先判断岗位族和职责主线。若职责是企业知识库、Agent 工作流和 FastAPI 交付，LangChain/RAG/Python 是 P0，Dify 是 P1，微调/K8s 多半是加分或团队协作边界。若职责是训练或 GPU 平台，则属于另一岗位族。用实际职责、学历、年限和项目描述共同判断，不能只数关键词。

### 练习 2：四年前端经验能否直接满足“3 年以上 Python/Java 开发经验”？

**答案：**不能直接等同。可以诚实写“四年软件工程与前端交付经验”，再用 Git 历史、测试、架构文档和可运行项目证明 Python Agent 后端能力。对明确要求三年 Python 商业经验的岗位降低匹配分，不伪造年限。

### 练习 3：为什么不把 LoRA 训练设为主项目必修？

**答案：**目标岗位是应用开发，当前设备也不适合本地训练。主项目更需要 RAG、Tool、状态、评测、安全和交付深度。课程仍补齐 Transformer、SFT/LoRA、量化和服务边界，以便面试选型；只有目标 JD 高频且明确要求训练实操时，再使用云端小模型实验升级。

### 练习 4：如何证明自己不是只会做 Demo？

**答案：**展示可重复测试、离线评测集、权限负向用例、迁移文件、队列失败重投、SLO、负载报告、Runbook、发布回滚和事故复盘。业务功能只是起点，失败时仍可控才是企业证据。
