# Token 成本、模型路由与调用治理

> 预计 6 小时｜产出：无固定金额上限、但 Usage 与异常增长可观测的调用治理层。

## 1. 成本可观测

每次调用记录输入/输出 Token、缓存 Token（如供应商提供）、单价版本、估算人民币成本、任务、模型和是否重试。价格会变化，计费表不能硬编码散落；放配置并标记生效日期。

成本按任务看，而非只看单次调用：一次 Agent 可能包含规划、三次工具、修复和总结。还要统计失败任务成本、P50/P95 与每成功任务成本。

## 2. 降本顺序

先消除无用调用与循环 → 压缩 Tool 结果/检索重复 → 小模型处理简单任务 → 缓存稳定结果 → 批量离线评测 → 最后才牺牲质量。盲目缩短 Prompt 可能破坏安全规则。

模型路由按规则与评测：结构抽取/分类用低价模型，复杂诊断候选用较强模型；高风险最终仍需证据与人工，不靠昂贵模型自动放权。

## 3. 调用治理

教程不分配月度金额，也不因累计费用自动拒绝请求。按日常交互、在线评测、演示和失败浪费四类统计；当单位成功任务成本或小时费用偏离历史基线时告警，重点排查循环、重复检索、上下文膨胀、多层重试和路由错误。

## 4. 项目任务

实现 `UsageMonitor` 与模型路由器；回放历史轨迹比较三种策略的成功率、延迟和成本。费用账与供应商后台抽样核对。

## 5. 练习与答案

### 练习 1：失败调用也要计费吗？

**答案：**很多情况下会产生 Token/请求费用；应按供应商 usage 记录，缺失时保守估算。

### 练习 2：费用突然升高时静默切到最便宜模型好吗？

**答案：**不好。先定位增长根因，并依据质量、延迟和业务风险决定路由；不能为降低费用而无评测地牺牲关键任务质量。

## 6. 验收与资料

Usage、费用和异常增长可观测，路由有对照评测，不存在教程预设金额上限。参考 [DeepSeek 计费](https://api-docs.deepseek.com/quick_start/pricing)、[阿里云百炼模型价格](https://help.aliyun.com/zh/model-studio/model-pricing)。
