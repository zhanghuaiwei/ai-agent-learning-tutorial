# 命令与故障速查

## 1. 环境与运行

```bash
uv python install 3.12
uv sync --frozen
uv run python -V
uv run uvicorn app.main:app --reload
uv run pytest -q
uv run pytest tests/unit -q
uv run pytest -m integration -q
uv lock --check
```

真实命令以项目 `pyproject.toml` 为准。不要在系统 Python 全局安装依赖。

## 2. HTTP/SSE 诊断

```bash
curl -sS http://127.0.0.1:8000/health/live
curl -N -H 'Content-Type: application/json' \
  -d '{"message":"查询 EQ-001"}' \
  http://127.0.0.1:8000/v1/chat/stream
```

SSE 无实时输出：检查代理缓冲、是否使用 `curl -N`、服务端是否真正 yield、同步阻塞、事件是否以空行结束。401 看 Token/Issuer/Audience；403 看 Scope/租户/资源；409 看幂等冲突；429 看调用方限流与重试风暴。

## 3. 分层排错顺序

```text
确定 request_id/run_id/thread_id
-> API 状态与日志
-> Graph 节点/Checkpoint
-> Tool 参数与权限
-> 检索候选与 ACL
-> 模型消息/结构验证
-> 依赖延迟、重试、费用
-> 业务数据库最终事实
```

RAG 答错先看标准证据是否存在，再看解析、Chunk、召回、重排、Context、生成，不直接换模型。Graph 卡住看当前 State、下一边、Interrupt、Checkpoint 与循环预算。

## 4. 常见故障

| 现象 | 优先检查 |
|---|---|
| Pydantic extra error | Provider/Tool 返回契约漂移 |
| Tool Message 错配 | `tool_call_id` 和消息顺序 |
| 请求反复重试 | 网关、SDK、Graph 是否多层重试 |
| 恢复后重复写 | Interrupt 前副作用、幂等键 |
| 跨租户结果 | 检索前 ACL、缓存 Key、Thread 所有权 |
| Token 突增 | 历史、重复 Chunk、Tool 大结果、循环 |
| CI 偶发失败 | 是否访问真实模型、时间/随机/测试顺序 |

## 5. 练习与答案

### 练习：工单请求超时，第一步再次 POST 吗？

**答案：**先用幂等键查询业务结果或按同 Key 安全重试；不能生成新 Key 盲目提交。
