> 每章复制一份。答案不是“看懂官方答案”，而是用代码、测试和口述证明。

```markdown

日期：
实际用时：阅读__ / 编码__ / 测试__ / 复盘__

## 我能解释
- 核心概念：
- 它解决的问题：
- 不能解决的问题：
- 一个替代方案与取舍：

## 练习
题目：
我的初始答案：

差异与误区：
我用什么代码/测试验证：

## 项目增量
提交或文件链接：
新增能力：
新增测试：
是否影响安全/费用/延迟：

## 失败案例
现象：

## 验收
- [ ] 不看资料可讲 3 分钟
- [ ] 基础与失败测试通过
- [ ] 已并入主项目
- [ ] 有 Trace/指标/结果证据
- [ ] 知道何时不用本技术

下周唯一补缺：
```

## 复盘规则

- 连续两章项目增量为空：暂停读新章，补实现。
- 只有成功截图、无测试：本章未完成。
- 能调用 API、不能解释错误和边界：本章最多 60%。
- 答案与教程不同不一定错，以官方契约、实验和业务约束验证。

## 练习与答案

### 练习：一章投入超过计划两倍仍未完成怎么办？

**答案：**缩到最小可验证目标，记录阻塞；优先完成核心路径和测试，把扩展放待办。不要无止境追求一次学全。
