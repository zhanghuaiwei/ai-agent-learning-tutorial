## 3. 费用异常状态机

```text
NORMAL：费用和每成功任务成本处于历史基线范围
NOTICE：单位任务成本或小时费用明显上升，标记并观察
INVESTIGATE：持续偏离基线，检查循环、重试、上下文和模型路由
INCIDENT：出现调用风暴或失控循环，按可靠性策略限流/熔断，而非按累计金额停用
```

异常阈值来自历史基线和具体业务 SLO，不由用户 Prompt 控制。失败/取消请求也计入台账；供应商后台账单与本地估算每周抽样对账。

## 4. 优化实验模板

```markdown
假设：减少重复 Chunk 可降低 20% 输入 Token 且忠实度不下降
基线：数据集/模型/Prompt/索引版本
候选：唯一改动
结果：任务成功、忠实度、P95、元/任务、方差
决定：保留/回滚
```

## 5. 练习与答案

### 练习 1：输入 Token 降 30% 就算优化成功吗？

**答案：**还要验证任务成功、忠实度、安全与延迟不退化；成本不是唯一目标。

### 练习 2：既然无金额上限，调用风暴是否也不应停止？

**答案：**不是。没有消费上限不等于没有可靠性边界。循环、异常重试或攻击造成的调用风暴应按限流、Deadline 和熔断策略停止；正常且有价值的开发与评测不受累计金额限制。
