# Agent 轨迹与 RAG 分层评测

> 预计 7 小时｜产出：不仅评最终文本，还评过程与副作用。

## 1. Agent 轨迹指标

- 是否选择允许的工具、参数是否有效。
- 必要工具是否调用、无关工具是否过多。
- 调用顺序是否满足审批和业务规则。
- 是否重复循环、是否在预算内终止。
- 副作用是否恰好一次，拒绝是否适当。

轨迹不要求与参考路径逐步完全一致；可以定义允许路径集合。例如先查告警后搜手册和反过来都合法，但提交必须在批准之后。

## 2. RAG 分层

把检索器单独评 Recall@k/MRR/ACL，把生成器固定证据评忠实度，再做端到端任务成功率。若端到端退化，分层结果能定位是索引、检索还是生成。

定义自动轨迹规范：`create_work_order` 前必须出现有效 `approval_id`；同一幂等键成功提交最多一次；越权工具调用为硬失败，不参与平均稀释。

## 3. 项目任务

实现轨迹解析器和三条安全不变量；建立检索、固定 Context 生成、端到端三个实验，生成失败漏斗。

## 4. 练习与答案

### 练习 1：最终回答正确但调用了无关写工具，算成功吗？

**答案：**不算。副作用和轨迹是任务正确性的一部分，安全违规应硬失败。

### 练习 2：为何不能要求轨迹与参考完全相同？

**答案：**开放任务可能有多条合法路径；过度约束会惩罚有效策略，应检查必要不变量和效率。
