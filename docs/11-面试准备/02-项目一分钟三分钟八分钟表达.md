# 项目一分钟、三分钟、八分钟表达

> 表达遵循：业务问题 → 约束 → 关键设计 → 量化证据 → 你的贡献 → 局限。

## 1. 一分钟版本

“我做的是工业设备维护知识与工单协同 Agent。它不是普通聊天机器人：先用混合 RAG 提供带版本、页码和权限的证据，再用 LangGraph 把告警查询、诊断、工单草稿、人工审批和幂等提交编排成可暂停恢复的流程。我对工具权限、Prompt Injection、跨租户、重复提交做了硬门禁，并用 LangSmith 数据集分别评检索、回答和轨迹。Python 是 Agent 主服务，可选 Spring Boot 服务拥有业务事务。最终指标我会按实际报告填写，不夸大线上规模。”

## 2. 三分钟版本

增加三段：

1. 为什么选 Hybrid RAG 与 Graph，而不是单 Agent。
2. 最难故障：Java 成功后网络超时，利用幂等键和调和避免重复。
3. 数据：Recall、引用忠实、越权/重复为零、P95、费用，以及已知局限。

## 3. 八分钟版本

按最终演示脚本展开：领域与边界 1 分钟；架构 1 分钟；RAG 1.5 分钟；Graph/审批/恢复 2 分钟；评测安全成本 1.5 分钟；故障故事和局限 1 分钟。每段准备面试官可能打断的位置。

不要背词。用结构卡片，每周录音两次；回看是否出现“然后、就是、调用一下”等模糊表达，是否能解释选择代价。

## 4. 练习与答案

### 练习 1：面试官只有 30 秒怎么办？

**答案：**一句业务价值 + 两个差异点（可恢复工作流、分层评测）+ 一个可量化结果，邀请对方选择想深入的部分。

### 练习 2：被问真实用户量怎么办？

**答案：**明确这是企业级作品而非生产上线，给测试规模和方法，不伪造用户；说明上线前还需真实场景验证。

## 5. 验收

三个版本均能脱稿、在时限内结束；每个技术名都能对应代码、测试或报告。
