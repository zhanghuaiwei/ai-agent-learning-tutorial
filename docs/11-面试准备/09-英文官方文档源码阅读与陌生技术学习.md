# 英文官方文档、源码阅读与陌生技术学习

> 目标：在框架快速变化的前提下，用英文官方资料和最小实验解决问题；不要求流利翻译全文，而要求找到契约、验证结论并留下证据。

## 1. 为什么这是岗位能力

Agent 生态更新快，中文视频和博客通常晚于官方版本。面试官可能给出：

- 一个陌生 SDK 文档；
- 一段框架报错或迁移说明；
- 一个 GitHub Issue/PR；
- 一个未使用过的 Tool/MCP/A2A 协议；
- 一段需要现场调试的代码。

评价重点是问题拆解、证据来源、最小复现和风险意识，不是记忆每个类名。

## 2. 文档阅读顺序

```text
Overview / Concepts
  → Quickstart（只建立最小路径）
  → Guides（当前任务）
  → API Reference（精确签名/类型）
  → Release Notes / Migration
  → Source / Tests / Issues
```

不要从搜索结果中的旧代码片段直接开始。先确认文档站点、语言版本、包版本和发布日期。

## 3. 一页文档的四次扫描

### 第一次：定位

只看标题、目录、Note/Warning/Deprecated、代码块和版本标签，判断页面是否回答当前问题。

### 第二次：提取术语

保留技术名词英文：durable execution、checkpoint、interrupt、lease、fallback。为每个词写一句中文业务含义，不逐字翻译。

### 第三次：找契约

关注：

- 输入/输出类型；
- 默认值；
- 生命周期；
- 并发/线程安全；
- 异常和重试语义；
- 安全警告；
- 实验性/弃用状态；
- 版本兼容。

### 第四次：最小验证

将示例缩为 20～50 行，只保留一个假设，运行并写断言。文档结论进入项目前必须有测试或可复现命令。

## 4. 英文不熟练时的做法

- 先读代码、表格和标题，再处理长段落；
- 只翻译阻塞理解的句子，不翻译整个页面；
- 建立术语表，不反复翻译同一个词；
- 对 `must/should/may`、`not thread-safe`、`deprecated` 等约束词特别敏感；
- 用自己的中文写“它保证什么、不保证什么”；
- 保留原链接、版本和引用位置，防止二次转述失真；
- AI 翻译结果要回到原文和最小实验核验。

## 5. 文档结论卡片

```markdown
# 技术结论：AutoGen Agent 并发共享

- 问题：一个 AssistantAgent 能否给多个请求并发复用？
- 本地版本：x.y.z
- 官方来源：链接 + 核验日期
- 官方约束：实例有状态，文档警告不可并发共享
- 最小实验：tests/experiments/test_agent_concurrency.py
- 项目决定：每 Thread 独立实例，由工厂创建
- 尚未确认：跨进程状态存储
```

卡片用于 ADR、面试复盘和升级检查，不复制大段原文。

## 6. 版本核对五件套

```bash
python --version
uv pip show langchain langgraph langsmith
uv tree
git rev-parse HEAD
git status --short
```

再核对：

- 文档 URL 是否属于 stable/latest/特定版本；
- 示例 import 路径是否与包一致；
- Release Notes/Migration 是否提到破坏变化；
- lockfile 是否实际锁住版本；
- 错误是否来自框架、Provider Adapter 或本项目封装。

## 7. 最小复现方法

一个好复现：

- 新建独立目录/测试文件；
- 固定依赖和 Python 版本；
- 用 Fake/最小输入消除业务噪声；
- 不包含真实 Secret 和数据；
- 一个命令运行；
- 明确 Expected/Actual；
- 包含完整异常和最小 Trace；
- 验证修复前失败、修复后通过。

不要把整个企业项目发给维护者并说“不能运行”。

## 8. 从 Trace 进入源码

阅读顺序：

1. 找到第一个属于本项目的栈帧；
2. 找到第一个框架栈帧；
3. 根据类/函数进入源码定义；
4. 阅读类型签名、docstring 和直接调用者；
5. 搜索对应测试；
6. `git blame`/PR/Issue 只在需要理解变更原因时使用；
7. 写最小断言验证，而不是仅凭源码猜测。

源码阅读不等于从仓库第一行开始。沿真实调用链回答一个具体问题。

## 9. 搜索仓库的顺序

优先使用：

```bash
rg 'ClassName|function_name|error text' src tests
rg 'deprecated|migration|breaking' .
rg --files | rg 'test|example|migration'
```

测试往往比实现更清楚地表达维护者认为的契约。类型定义帮助确认 State、Message 和 Event 的形状。

## 10. 阅读 Issue 和 PR

先判断：

- 是否官方仓库；
- Open/Closed/Merged；
- 对应版本和复现条件；
- 维护者结论还是用户猜测；
- 是否已有替代方案；
- Workaround 会否破坏安全/一致性。

一个未合并 PR 不是正式 API。社区答案与当前代码冲突时，以对应版本实现、测试和官方说明为准。

## 11. 陌生框架 90 分钟实验

| 时间 | 任务 |
| ---: | --- |
| 0～10 分钟 | 明确一个业务问题和成功标准 |
| 10～25 分钟 | 读 Overview/Concepts，画抽象映射 |
| 25～40 分钟 | 安装并固定版本，跑最小示例 |
| 40～65 分钟 | 接统一 Model/Tool/State 契约 |
| 65～80 分钟 | 加一个失败/取消/权限测试 |
| 80～90 分钟 | 写结论、限制和下一步 |

若 90 分钟仍停留在安装，记录环境阻塞和官方 Issue，不伪造比较结论。

## 12. 论文阅读边界

应用岗读论文采用五问：

1. 解决什么问题，基线是什么？
2. 核心机制能否用一张图解释？
3. 实验数据与指标是否接近本业务？
4. 假设、成本和失败边界是什么？
5. 能设计怎样的最小业务实验？

无需逐行推导所有公式，但 Transformer、Embedding、RAG、ReAct 等核心论文要能解释关键思想。论文 Demo 不能直接当生产方案。

## 13. 使用 AI 辅助阅读的安全方式

可以让 AI：

- 解释术语和代码；
- 生成待验证假设；
- 对比两个版本的 API；
- 帮助构造最小测试；
- 总结 Release Notes。

必须人工核验：

- 精确函数签名和默认值；
- 版本/发布日期；
- 安全、并发和事务语义；
- 删除、费用和数据保留；
- AI 提供的链接和引用。

禁止把公司私有代码、Secret、客户数据直接上传未知服务。

## 14. 现场陌生 API 题答法

1. 复述目标和输入输出；
2. 声明尚不熟悉该 SDK，但说明会从官方契约定位；
3. 找最小调用和类型；
4. 封装 Adapter，避免业务耦合；
5. 处理超时、错误和资源关闭；
6. 写一个 happy path 和一个失败测试；
7. 说明尚未验证的假设。

坦诚未知并快速验证，比猜 API 更专业。

## 15. 开源 Issue/PR 练习

从教程或依赖中选择一个真实小问题：

- 文档错误；
- 过时链接；
- 示例缺少版本说明；
- 可复现的边界 Bug；
- 类型/错误提示改进。

提交前：搜索重复 Issue、阅读贡献指南、运行测试、写最小复现。PR 描述包含 Problem、Change、Test、Risk，不把自动生成的大规模改写直接推给维护者。

这是英语、源码、协作和工程判断的综合证据。

## 16. 每月版本雷达

只跟踪与项目有关的组件：

| 组件 | 当前锁定 | Latest | Breaking/Migration | 处理 |
| --- | --- | --- | --- | --- |
| Python | | | | |
| LangChain | | | | |
| LangGraph | | | | |
| LangSmith | | | | |
| MCP SDK/Spec | | | | |
| Pydantic/FastAPI | | | | |

升级顺序：读 Release Notes → 建分支 → 更新 lock → 跑契约/评测 → 检查 Trace/成本 → 记录 ADR。不要在项目交付前无理由追 Latest。

## 17. 练习与答案

### 练习 1：官方 Quickstart 能运行，是否证明用法适合生产？

**答案：**不能。Quickstart 只证明最小 happy path。还要查看并发、状态、错误、安全、持久化、部署和版本说明，并做项目失败实验。

### 练习 2：中文博客与当前官方文档冲突怎么办？

**答案：**先核对双方版本，以本地锁定版本的官方 API、源码测试和最小复现为准。博客可解释背景，但不能替代契约。

### 练习 3：AI 总结说某 Agent 实例线程安全，是否可以采信？

**答案：**不能直接采信。查官方并发警告、源码状态字段和测试，再做并发最小实验。错误结论可能造成跨用户状态泄漏。

### 练习 4：源码看起来会自动重试，为什么仍要测试？

**答案：**重试条件、次数、异常映射和副作用语义可能与理解不同，也可能由配置或 Adapter 改变。测试验证当前版本和实际组合。

## 18. 面试追问

1. 如何在一天内上手陌生 Agent 框架？
2. 如何判断文档示例是否过时？
3. 从报错进入源码的路径是什么？
4. 如何写高质量最小复现？
5. 如何利用 AI 阅读英文文档又避免幻觉？
6. 为什么测试比阅读实现更适合确认契约？
7. 依赖何时升级、何时冻结？

## 19. 验收标准

- [ ] 为三个核心问题各写一张文档结论卡；
- [ ] 完成一个陌生框架 90 分钟迁移实验；
- [ ] 从一次真实 Trace 定位到依赖源码和测试；
- [ ] 提交一个最小复现 Issue 或文档/代码 PR；
- [ ] 建立每月版本雷达；
- [ ] 能用中文准确解释英文约束，不依赖全文翻译；
- [ ] 所有重要结论包含版本、官方链接和实验。
