# Agent 高频原理与追问题

> 预计 6 小时｜目标：把 Tool/Memory/RAG/Graph/Eval/MCP 六大主题的高频原理题练成"90 秒口述 + 失败路径追问"的反应，每题都落回智维 Agent 的取舍。

> **阅读前置**：第 11 阶段（面试准备）原理训练。前置依赖：M0～M6 已动手——原理题只有在"讲你做过的系统"时才可信，没有项目证据的背诵会被追问到崩。使用方法：先口述 90 秒，再看答案补缺；每题继续追问失败路径和取舍。

## 1. 本章从哪里开始

项目表达（02 章）把面试官引到了六大主题：Tool、Memory、RAG、Graph、Eval、MCP。面试官会顺着这些名词往下追问原理，再追问失败路径。背定义只够第一层，第二层"失败怎么办"、第三层"你怎么证明"才是分水岭。

本章把六大主题拆成高频题，每题按"答案要点 + 失败路径追问 + 项目取舍"三层组织。你的目标不是记住答案，而是把答案里的每个判断，都对应到自己的代码/测试/ADR。

## 2. 本章完成标准（通过门槛）

- 六大主题各能**不看稿口述 90 秒**；
- 每道题都能追加三个追问（为什么选 / 失败怎么办 / 怎么证明）；
- 每个追问答案能落到项目的 ADR、故障注入或指标；
- 原理表述与教程各阶段术语一致（`search_manual`/`get_alarm`/`create_work_order_draft`、`AgentAnswer`、`E_*`、SSE 12 事件、分层评测指标）。

## 3. Tool 主题

### 3.1 Agent 与 Workflow 有何区别？

**答案要点：**Agent 让模型在边界内动态选动作；Workflow 由代码预定路径。生产常混合：语义判断用模型，权限、审批、事务、停止由确定性系统控制。

**失败路径追问：**模型选错工具怎么办？→ 工具描述可区分 + 参数校验 + 工具选择准确率评测；模型反复调同一个工具？→ 循环检测，命中 `run.execution_limit_reached`。

**项目取舍：**智维 Agent 用单 Agent 做"查手册 → 查告警 → 建工单草稿"的动态选择，但建单前有审批、写操作有幂等，权限在 `scope` 检查而非 Prompt。

### 3.2 Function Calling 如何执行？

**答案要点：**模型只生成工具建议和参数；应用校验 Schema、身份、权限与副作用，执行后返回 Tool Message。追问：未知工具、参数修复、幂等、超时。

**失败路径追问：**参数格式错？→ `E_INVALID_ARGUMENT`，有限提示一次；越权？→ `E_FORBIDDEN`，安全终止不重试；写超时结果未知？→ 按幂等键查询，不盲目重做。

**项目取舍：**模型输出永远不可信，`tenant_id` 来自服务端 `AgentContext`，不让模型填写；`create_work_order_draft` 是 `reversible_write`，靠 `idempotency_key` 防重复。

## 4. Memory 主题

### 4.1 Memory 有哪些？

**答案要点：**Thread 短期状态、跨 Thread 长期 Store、业务数据库事实；分别有作用域、来源、保留和删除。摘要不可替代权威事实。

**失败路径追问：**Memory 被注入污染？→ 写入前分类/去重/来源，租户隔离 + 用户删除；长期记忆过期？→ 明确的保留与删除策略。

**项目取舍：**设备/工单等权威事实在业务数据库，不由模型 Memory 覆盖；向量库不是业务事实库，长期偏好要有来源和删除。

## 5. RAG 主题

### 5.1 为什么需要 RAG，而不是全塞进 Prompt？

**答案要点：**企业文档有版本、页码、权限和规模，塞进 Prompt 会超长、无法引用、无法删除。RAG 把文档拆成可检索、可引用、可评测的证据片段。

**失败路径追问：**检索到其他租户文档？→ 服务端 ACL 过滤 + 索引命名空间隔离，不能先取回跨租户 Chunk 再让模型忽略；文档删除怎么同步？→ 数据血缘逐层删除。

**项目取舍：**`search_manual` 返回精简片段 + `evidence_ids`，不是 2 万字正文；分层评测用 Recall@K 和引用忠实度，分别测"找到没有"和"答得准不准"。

### 5.2 如何防幻觉？

**答案要点：**按失败类型处理：事实用 RAG/Tool 和引用，格式用 Schema，业务动作由确定性校验，信息不足时拒答；用数据集评测而不是承诺"消除幻觉"。

**失败路径追问：**引用错误？→ 引用忠实度评测；信息不足还硬答？→ 拒答（`AgentAnswer` 拒绝态）。

**项目取舍：**`AgentAnswer` 的结构化输出约束回答格式，工具只回 `evidence_ids`，最终引用由检索命中决定而非模型自由编造。

## 6. Graph 主题

### 6.1 为什么需要 LangGraph？

**答案要点：**显式 State/Node/Edge、Checkpoint、Interrupt、恢复和故障重放，适合跨请求、审批和复杂流程。简单工具循环用 `create_agent` 即可。

**失败路径追问：**进程在批准后、写业务 API 前崩溃？→ 恢复后读 Approval 和幂等记录，用同一 `idempotency_key` 提交；超时未知先查询业务服务。

**项目取舍：**工单流程跨请求、含人工审批，用 LangGraph 的 Checkpoint/Interrupt；简单问答仍用单 Agent，不为一律上 Graph。

### 6.2 如何防 Agent 死循环？

**答案要点：**最大步数、总期限、Token、重复动作检测、工具次数、不可恢复错误、人工中断；监控步数分布并以数据调整。

**失败路径追问：**相同工具不同参数算不算循环？→ 相同工具 + 规范化参数连续 2 次才算，避免误伤"先查 A 告警、再查 B 告警"。

**项目取舍：**执行边界建议值——最大模型调用 4 次、最大 Tool Call 6 次、总 Deadline 20 秒、循环检测连续 2 次；命中进入 `run.execution_limit_reached` 终态。

## 7. Eval 主题

### 7.1 Agent 怎么测试？

**答案要点：**确定性单元/契约/E2E + 概率性数据集评测；既测最终答案，也测 Tool 轨迹、权限、终止、副作用、成本和安全。

**失败路径追问：**LLM Judge 指标很好但人工不满意？→ 抽样校准 Judge、查 Rubric 与数据分布，引入人工金标和规则评测，不靠更多 Judge 掩盖。

**项目取舍：**分层评测指标——检索 Recall@K、引用忠实度、工具选择准确率、越权拦截率、任务终止率，各自脚本化断言，不是一句"准确率高"。

## 8. MCP 主题

### 8.1 什么是 MCP，什么时候用？

**答案要点：**MCP 是让外部 Tool/Resource 以标准协议接入的规范，Client 与 Server 之间按能力协商。适合独立组织、可复用的外部工具接入；内部工具直接用代码绑定更简单。

**失败路径追问：**MCP Server 越权怎么办？→ OAuth 授权 + 最小 Scope + 参数校验 + 审计，与本地工具同一套权限原则；Server 不可用？→ 降级或报 `E_UPSTREAM_TIMEOUT`。

**项目取舍：**企业内部 Java 服务通过 MCP Adapter 暴露，但授权仍在服务端；MCP 是协议接入，不替代权限、审批和幂等。

### 8.2 多 Agent 何时有价值？

**答案要点：**职责、上下文和工具确实可隔离且能独立评测时；否则子图/函数更简单。必须量化质量收益、成本、延迟与故障面。

**失败路径追问：**多 Agent 怎么终止？→ 每个 Agent 有自己的执行边界和终止条件；上下文怎么隔离？→ 各自的 State/Scope。

**项目取舍：**当前单主图 + 子图即可表达职责与权限，暂不拆多 Agent，避免增加 Prompt、上下文、终止、评测与成本。

## 常见错误与诊断顺序

### 10.1 背定义不背失败路径

只背"Checkpoint 是快照"这类定义，追问"崩溃后怎么恢复"就答不出。诊断顺序：每题先补"失败怎么办"，再补"怎么证明"，最后才是定义。

### 10.2 原理与项目脱节

答案全是通用话术，落不到智维 Agent。诊断顺序：把每题答案里的名词替换成项目实体（`get_alarm`、`E_FORBIDDEN`、SSE 12 事件），说不出的就回项目补。

### 10.3 夸大"消除幻觉/彻底防注入"

承诺"彻底消除幻觉""完全防注入"。诊断顺序：改成按失败类型处理和"无法只靠识别文本彻底消除注入"，用评测证明而非绝对化。

### 10.4 把所有场景都上 Graph/多 Agent

不问业务就上 Graph、拆多 Agent。诊断顺序：回到"是否跨请求/有审批/有恢复"和"是否可隔离且能独立评测"的判据，简单场景用普通代码或单 Agent。

## 练习题与答案

### 练习 1：选两题，各追加三个追问。

**示例答案：**"为什么选择""失败怎么办""如何证明"是通用追问；回答必须落到本项目的 ADR、故障注入和指标。例如"为什么 LangGraph"追问到"批准后崩溃怎么办"，答"读 Approval + 幂等记录，同一 key 提交"。

### 练习 2：面试官问"Function Calling 里的工具参数能信吗？"

**答案：**不能。模型只生成候选参数；应用校验 Schema，身份/权限来自服务端 `AgentContext`，`tenant_id` 不让模型填写；越权返回 `E_FORBIDDEN` 安全终止。

### 练习 3：为什么"多 Agent"不是默认更先进？

**答案：**多 Agent 只有在职责、上下文、工具确实可隔离且能独立评测时才有价值；否则增加 Prompt、上下文、终止、评测和成本。当前单主图 + 子图更简单，需对照评测证明收益才拆分。

### 练习 4：评测"准确率"够不够？

**答案：**不够。分层评测才能定位问题：Recall@K 测检索、忠实度测引用、工具选择准确率测选型、越权拦截率测安全、任务终止率测循环有界，分别脚本化断言。
