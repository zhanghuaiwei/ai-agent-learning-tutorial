# 模拟面试记录与补缺

> 第 22～24 周至少完成 6 次：项目 2、原理 1、系统设计 2、综合 1。

## 1. 记录模板

```markdown
日期/面试类型/时长/面试官：
题目与追问：
我的回答摘要：
证据是否充分：0/1/2
结构是否清晰：0/1/2
技术是否正确：0/1/2
取舍是否具体：0/1/2
暴露的唯一主要缺口：
48 小时修复任务：
验证方式与链接：
复测日期：
```

每次只选一个最高收益缺口进入 48 小时修复，避免列十项却都不完成。修复必须产生代码、测试、图、ADR 或口述复测之一。

## 2. 六次安排

1. 不看稿完成 3 分钟项目与追问。
2. Agent/RAG/LangGraph 原理快问快答。
3. 企业知识工单系统设计。
4. 客服或研发助手陌生系统设计。
5. 故障、安全、成本压力面。
6. 完整 60 分钟，含 Python/SQL 基础。

录音回听，统计模糊词、超时、未回答问题、无证据断言。第六次应由不熟悉项目的人执行，避免熟人自动补全上下文。

## 3. 练习与答案

### 练习 1：连续两次讲不清 Reducer，继续背题好吗？

**答案：**不好。回到最小 Graph 写并发更新测试，再画状态合并，最后口述；用产出修补心智模型。

### 练习 2：模拟面试分数波动怎么办？

**答案：**看同类问题趋势与具体证据，统一评分 Rubric；目标是发现缺口和提高稳定表达，不追求一次高分。

## 4. 投递节奏

先小批量投递校准简历，根据反馈修正后进入目标公司批次。每次真实面试只记录不涉公司机密的题型与自身缺口，24 小时内复盘。
