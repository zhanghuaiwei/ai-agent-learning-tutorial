# 西安岗位检索与 JD 能力映射

> 第 24 周前持续执行｜不要只搜索“Agent 工程师”一个职位名。

## 1. 搜索词

组合搜索：`大模型应用开发/AI 应用工程师/智能体/Agent/RAG/知识库/LLM 工程师/AI 平台 + 西安`。同时看 Python 后端含 AI、Java/Python AI 集成、解决方案研发岗位。

截至 2026-08 的公开样本已出现西安岗位明确要求 Python、LangChain/LangGraph、RAG、工具调用、上下文管理、异常处理、评测和外部系统集成。这只是方向证据，不代表后续岗位数量；投递期必须重新采样。

第二轮样本还反复出现 FastAPI、SQL/Redis、分布式任务/MQ、Dify、部署排障、需求分析和技术文档。详细样本、岗位族和必修/加分边界见[岗位能力再审计](../01-总览与使用方式/08-岗位能力再审计.md)。

西安未来五年政策方向明确提到“算力+高质量数据集+大模型+AI 应用”、行业大模型和智能体、AI+制造；同时商业航天、低空、智能制造、文旅等有场景。作品选择工业维护能覆盖通用企业知识/流程，又能映射当地制造和空天产业，但不把求职限制在单行业。

## 2. 每周 JD 采样

每两周采样 10 条，临近投递加密为每周 15 条。表格字段：公司/行业/职级/职责/必需/加分/学历/年限/技术词/业务词/缺口/作品证据/投递状态/日期/链接。过期 JD 仍保留快照和采样日期。

## 3. 能力映射

| JD 高频能力 | 本课程证据 |
|---|---|
| Python/FastAPI/异步 | M0 API、超时、取消、测试 |
| Redis/MQ/后台任务 | 摄取 Job、重复投递、Outbox 与 DLQ |
| LangChain/Tool | M2 工具助手 |
| RAG/向量库 | M3 分层评测报告 |
| LangGraph/Workflow | M4 暂停恢复与幂等 |
| 评测/优化 | M5 Dataset/Experiment |
| 工程部署 | M6 CI、故障、成本、安全 |
| Dify/低代码平台 | 同一流程的 Dify/LangGraph 对照 ADR |
| 模型原理/微调/推理边界 | 模型选型卡与微调决策 ADR |
| 企业集成 | Java API/MCP Adapter |
| 需求到上线 | RFC、Readiness Review、回滚演练和验收纪要 |

若 30 条目标 JD 中某技能出现 ≥30% 且作品无法证明，进入补缺；低频技术不要打乱主线。

## 4. 练习与答案

### 练习 1：JD 写 vLLM/K8s，是否立刻改主线？

**答案：**先看目标样本频率和“必需/加分”。本课程低配且偏应用，先能解释部署边界；若高频必需，再安排受控补充，不牺牲 Agent 核心。

### 练习 2：已有工作经验如何定位？

**答案：**作为产品交付、协议和用户体验优势；简历主叙事是后端 Agent 可靠性，不把自己写成只会接模型的工程师。

### 练习 3：JD 标题是“AI 应用研发”，但职责全是 vLLM、GPU 调度和 K8s，是否属于主投岗位？

**答案：**标题不能决定岗位族。该职责更接近推理 Infra/AI 平台底座，不是默认主投；除非已经有真实部署与调优证据，否则降低匹配，而不是在简历堆关键词。
