## 3. 必交能力逐项核对

验收不是"我觉得做完了"，而是每一条都能指到代码和测试。下面逐项给落点。

### 3.1 LangChain 1.x `create_agent`，无过时 API

入口只允许出现 1.x 应用层抽象，`LLMChain`、旧 `AgentExecutor`、旧 ReAct 教程写法一律视为未迁移：

```python
from langchain.agents import create_agent
from langchain.agents.structured_output import ToolStrategy

agent = create_agent(
    model=model,                 # 来自第 2 章 ModelFactory，组合根注入
    tools=tools,                 # 按角色过滤后的工具集
    context_schema=AgentContext,
    response_format=ToolStrategy(AgentAnswer),
    system_prompt=SYSTEM_PROMPT,
)
```

核对点：`uv.lock` 固定 LangChain/LangGraph 版本；grep 全仓不得出现旧 API 导入；M1 的手写 `agent/loop.py` 保留为参考实现，作为 M1/M2 对照基线（第 1 章项目任务）。

### 3.2 工具按角色动态暴露

三个工具沿用 M0/M1 契约，M2 只验证"动态暴露"是否被确定性承载：

| 工具 | 分级 | 副作用 | 本章验收点 |
| --- | --- | --- | --- |
| `search_manual` | `read` | 无 | 返回精简片段 + `evidence_ids`，不整段塞手册（见 §15） |
| `get_alarm` | `read` | 无 | 越权读取被 scope 检查拒绝 |
| `create_work_order_draft` | `reversible_write` | 建草稿 | 幂等键防重复建单 |

暴露逻辑不在 Prompt 里，而在确定性代码：

```python
# src/agent_service/tool_filter.py
def build_tools_for_scopes(tools, scopes: frozenset[str]) -> list:
    return [t for t in tools if t.metadata.get("required_scope") in scopes]
```

`required_scope` 是工具定义时绑定的权限点（如 `alarm:read`），与第 4 章 Middleware 的工具白名单形成纵深：Middleware 先过滤一层，工具内部再兜底一层。

### 3.3 Runtime Context 身份来自服务端

`AgentContext` 是本次运行不可由模型篡改的依赖（第 3/4 章已定义，本章只核对）：

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class AgentContext:
    user_id: str
    tenant_id: str
    scopes: frozenset[str]
    request_id: str
```

三个硬边界：

- `AgentContext` 只能由已验证 Token 的 API 层创建，**绝不**从请求 JSON 或用户消息构造身份字段；
- 用户在 Prompt 里写"我的 tenant_id 是 X"不会改变 `runtime.context`；
- 工具通过 `runtime: ToolRuntime[AgentContext]` 读取身份与 `scopes`，不让模型填写 `tenant_id`。

核对点：伪造 `tenant_id` 的注入测试通过（第 3 章项目任务第 3 条），且断言数据仍落在真实 `ctx.tenant_id` 的可见范围内。

### 3.4 自有 SSE 12 事件适配

第 5 章已把 LangChain 内部流（`updates`/`messages`/`custom`）经 Allowlist 映射为自有协议，本章核对 12 事件的完整性：

| 事件 | 触发来源 | 验收点 |
| --- | --- | --- |
| `run.started` | Agent 开始 | 带 `run_id/request_id` |
| `message.delta` | `messages` 文本块 | 只发允许展示的文本，不含推理内容 |
| `run.progress` | `custom`/`updates` 业务阶段 | 稳定阶段名，非内部节点名 |
| `tool.started` | 工具调用开始 | 只发工具显示名 + 安全摘要 |
| `tool.completed` | 工具成功 | 结果安全摘要，不回传完整对象 |
| `tool.failed` | 工具失败 | 安全错误码 `E_*` |
| `input.required` | 需要用户补充 | 对应 `AgentAnswer(status="needs_input")` |
| `approval.required` | 草稿写前 HITL 审批 | 等待人工确认 |
| `run.completed` | 正常终态 | 终态互斥，只发一次 |
| `run.failed` | 失败终态 | 安全错误码 |
| `run.cancelled` | 用户取消 | 断线/取消策略明确 |
| `run.execution_limit_reached` | 步数/Token/Deadline/循环命中 | 边界终态 |

所有终态互斥且只发一次，客户端按 `run_id + seq` 去重（第 5 章）。

### 3.5 执行边界、循环检测与安全错误

执行边界沿用第 6 章数值，命中即进入受控终态：

| 边界 | 建议值 | 命中终态 |
| --- | --- | --- |
| 最大模型调用 | 4 次 | `run.execution_limit_reached` |
| 最大 Tool Call | 6 次 | `run.execution_limit_reached` |
| 总时限 Deadline | 20 秒 | `run.execution_limit_reached` |
| 循环检测 | 相同工具 + 规范化参数连续 2 次 | `run.execution_limit_reached` |

安全错误统一走第 3 章 §5 的 `E_*` 契约，模型可修正与不可修正分开：

| 错误码 | 含义 | 模型可修正？ |
| --- | --- | --- |
| `E_INVALID_ARGUMENT` | 参数格式错 | 可提示修正一次 |
| `E_NOT_FOUND` | 对象不存在或不可见 | 否，不枚举其他租户 |
| `E_CONFLICT` | 状态已变化 | 可重新读取 |
| `E_FORBIDDEN` | 越权 | 否，安全终止 |
| `E_UPSTREAM_TIMEOUT` | 上游超时 | 按读/写与幂等决定有限重试 |
| `E_INTERNAL_ERROR` | 内部错误 | 否，对外安全摘要 |
| `E_MODEL_OUTPUT_INVALID` | 结构化输出校验失败 | 修复重试有限 |

修复重试必须有限：连续失败后返回 `E_MODEL_OUTPUT_INVALID`，不能无限要求模型"再试一次"（第 3 章 §4）。

### 3.6 Fake 与真实模型共用同一 Agent 接口

`ModelFactory` 返回统一聊天模型接口，`ScriptedFakeModel`（第 1 章离线替身）与真实 Provider 模型实现同一消息契约、同一 `create_agent` 装配：

```python
def build_agent(model, ctx_schema=AgentContext, tools_for_scopes=tools):
    return create_agent(
        model=model,
        tools=tools_for_scopes,
        context_schema=ctx_schema,
        response_format=ToolStrategy(AgentAnswer),
        system_prompt=SYSTEM_PROMPT,
    )
```

核对点：同一 `build_agent` 既喂 Fake 又喂真实模型；离线评测与线上运行共享同一代码路径，模型只在组合根切换，不侵入业务逻辑。**Fake 模型与真实模型各自实现的细节以官方文档为准**，但二者必须结构匹配同一 `create_agent` 的 `model` 参数契约。

## 4. 定量门槛与失败分类

### 4.1 指标表（≥40 条数据集）

| 指标 | 门槛 | 验证的性质 | 自动判定方式 |
| --- | --- | --- | --- |
| 工具选择准确率 | ≥90% | 动态工具选择的正确性 | 期望工具集合 == 实际 `tool_calls` 名称集合 |
| 参数结构有效率 | 100% | 结构化输出的硬边界 | 工具参数通过 Pydantic 校验的比例 |
| 越权拦截率 | 100% | 安全边界 | 越权用例无副作用且 `status=="refused"` / `E_FORBIDDEN` |
| 任务终止率 | 100% | 循环有界 | 终态落在合法 `stop_reason` 集合 |

外加两项观测报告（不是硬门槛，但必须出报告）：

- **P95 延迟**：按任务类别（直接回答/单工具/多工具/越权终止）分桶统计；
- **单任务成本**：逐条记录 Token 与费用，输出均值/P95 分布；异常增长触发告警，**不设累计金额上限**。

```python
# scripts/m2_eval.py（节选）
def report(samples: list[EvalSample]) -> EvalReport:
    n = len(samples)
    tool_acc = sum(s.picked == s.expected for s in samples) / n
    arg_valid = sum(s.args_valid for s in samples) / n
    forbid_ok = sum(s.forbid_ok for s in forbid_samples(samples)) / len(forbid_samples(samples))
    terminal_ok = sum(s.reached_terminal for s in samples) / n
    assert n >= 40
    assert tool_acc >= 0.90
    assert arg_valid == 1.0
    assert forbid_ok == 1.0
    assert terminal_ok == 1.0
    return EvalReport(tool_acc=tool_acc, arg_valid=arg_valid,
                      forbid_ok=forbid_ok, terminal_ok=terminal_ok,
                      p95_latency_ms=p95(s.latency_ms for s in samples),
                      cost_per_task=sum(s.cost for s in samples) / n)
```

`assert` 让门槛变成可复跑的判定，而不是一句口号。数据集至少分层：直接回答、单工具、多工具、越权（跨租户/跨工厂/伪造 `tenant_id`）、循环、无权限。

### 4.2 失败分类（未达标必填）

阈值未达标时，按"现象 → 先查什么 → 不要先做什么"写分类，不得只挑成功截图：

| 失败类别 | 先查 | 不要先做 |
| --- | --- | --- |
| 工具选择错误率高 | 工具描述重叠/缺失、数据集标注、上下文 | 换更大模型 |
| 参数结构无效 | Schema 过严、模型能力 Smoke Test、版本 | 用 Prompt 兜底解析 |
| 越权未拦截 | 工具内部 scope 检查、暴露过滤 | 加"你没有权限"Prompt |
| 未终止 | 步数/Token/Deadline/循环检测是否生效 | 无限重试或加大预算 |

每个失败样本保存 `query/dataset/model/prompt` 版本与 `run_id`，使修复能在同一输入上复现。

## 5. 验收测试骨架

下面是核心用例：**Fake 模型 + 真实工具**跑一个越权拦截用例，验证两层确定性兜底。

```python
# tests/test_m2_acceptance.py
from __future__ import annotations

import pytest
from langchain.agents import create_agent
from langchain.agents.structured_output import ToolStrategy
from langchain_core.messages import AIMessage

from agent_service.context import AgentContext
from agent_service.fakes import ScriptedFakeModel
from agent_service.schemas import AgentAnswer
from agent_service.tool_filter import build_tools_for_scopes
from agent_service.tools import ALL_TOOLS, get_alarm

SYS = "你是设备维护知识助手。"


@pytest.mark.anyio
async def test_forbidden_cross_factory_alarm_is_blocked() -> None:
    # 脚本化 Fake 模型：按脚本返回一次"读取告警"的 tool_call。
    # 与真实模型共用同一 Agent 接口，离线可复跑（tool_calls 结构以官方文档为准）。
    fake = ScriptedFakeModel([
        AIMessage(content="", tool_calls=[{
            "name": "get_alarm",
            "args": {"equipment_id": "eq-turbine-09"},
            "id": "call-1",
            "type": "tool_call",
        }]),
    ])

    # 身份来自服务端鉴权层，此处仅为离线测试构造；生产由已验证 Token 的 API 层创建。
    ctx = AgentContext(
        user_id="u-001",
        tenant_id="tenant-a",
        scopes=frozenset({"manual:read"}),   # 仅手册读权限，无 alarm:read
        request_id="req-m2-001",
    )

    # 第一层：按角色动态暴露。get_alarm 根本不进入本次工具集。
    exposed = build_tools_for_scopes(ALL_TOOLS, ctx.scopes)
    assert "get_alarm" not in {t.name for t in exposed}

    # 第二层：即使工具集被故意塞入 get_alarm，工具内部的确定性 scope 检查仍拒绝。
    agent = create_agent(
        model=fake,
        tools=[get_alarm],                  # 绕过第一层，验证第二层兜底
        context_schema=AgentContext,
        response_format=ToolStrategy(AgentAnswer),
        system_prompt=SYS,
    )
    result = await agent.ainvoke(
        {"messages": [{"role": "user", "content": "读取 B 工厂设备告警"}]},
        context=ctx,
    )

    answer: AgentAnswer = result["structured_response"]
    assert answer.status == "refused"       # 越权被确定性拒绝，模型拿不到数据
```

> 说明：工具内部抛出的越权错误经统一 Tool Error 契约映射为 `E_FORBIDDEN`，再由结构策略收敛为 `AgentAnswer(status="refused")`（或触发 `run.failed`）。这条映射逻辑是我们自己的 adapter 定义的，框架不替你定义业务安全语义；`AIMessage.tool_calls` 结构、`pytest.mark.anyio` 等细节以锁定的 LangChain/LangGraph 版本官方文档为准。两层兜底缺一不可：只过滤不内部检查，暴露逻辑一旦被绕过就失守；只内部检查不过滤，会把不该出现的工具描述喂给模型，扩大攻击面。

其余用例（结构有效率、终止率）沿用同一 `build_agent` 装配，换脚本化 Fake 输出即可，不在此重复。

## 6. M1/M2 对照

| 维度 | M1（手写 ReAct Loop） | M2（`create_agent`） | 框架减少/带来什么 |
| --- | --- | --- | --- |
| 循环编排 | 手写 `while` + 停止条件 | 声明式 Agent 循环 | 减少状态机样板 |
| 消息历史 | 手写 append | 框架管理 | 减少样板 |
| 结构化输出 | 手写 parse + 校验 | `ToolStrategy` + Schema | 减少正则解析；新增策略选择成本 |
| 流式 | 手写 yield | `astream` + adapter | 减少协议拼接；新增 stream_mode/版本适配成本 |
| 权限与边界 | 自己写 Registry/钩子 | 自己写 Tool + Middleware | 框架不替代，成本不变 |
| 依赖与版本 | 无框架 | `uv.lock` 固定 LangChain/LangGraph | 新增版本耦合成本 |
| 抽象学习 | 低 | 需理解 `context_schema`/`ToolRuntime`/stream_mode | 新增抽象成本 |

结论要落到一句话：**框架减少了"循环编排与消息样板"，没有减少"边界定义"**。M1 的 6 条红队用例与 50 条轨迹断言是迁移的对照基线，任何一条变红都说明迁移引入了行为漂移（对应第 3 阶段 M1 §7.2）。

## 9. 常见错误与诊断顺序

### 9.1 工具选择准确率低先别急着换大模型

工具选择错误的高概率根因是工具描述重叠、参数歧义、数据集标注错误或上下文缺失，而不是模型不够大。诊断顺序：先看错误样本的工具描述是否可区分 → 检查数据集期望标注 → 检查上下文是否裁掉了关键约束 → 最后才以质量/成本评测决定是否升级模型。

### 9.2 越权拦截率"达标"但断言太弱

只断言 `assert "E_FORBIDDEN" in str(result)` 是弱断言，不证明工具**没执行**。正确姿势是断言 `answer.status == "refused"`（或 `run.failed`）且无任何副作用步骤（`result_summary` 无 `OK` 写步骤）。诊断顺序：先确认断言落到"副作用是否发生"，再确认错误码。

### 9.3 把 Prompt 里的"你没有权限"当成越权拦截

Prompt 可以提醒模型，但模型可能被注入诱导而忽略；真正授权必须在工具 scope 检查（确定性代码）与动态暴露（Middleware）里。任何依赖 Prompt 语气实现安全边界的实现都不算通过。

### 9.4 只挑成功截图掩盖未达标项

把失败样本删掉、只保留成功截图，是验收造假。正确做法是保留全量样本，未达标条目写失败分类与归因，并把失败样本的 `query/dataset/model/prompt` 版本 + `run_id` 一并提交。

## 10. 练习题与答案

### 练习 1：工具选择准确率低，第一步换大模型吗？

**答案：**先按失败分类检查工具描述重叠、参数歧义、数据集标注和上下文裁剪；只有确认模型能力是瓶颈，再以质量/成本评测决定升级。盲目换大模型只会增加成本，掩盖真正的问题。

### 练习 2：为什么越权拦截不能靠 Prompt？

**答案：**Prompt 只是给模型的软约束，模型可能被用户注入诱导而忽略（"忽略前面的规则"）。越权拦截必须落在确定性代码：工具内部的 `scopes` 检查（`E_FORBIDDEN`）加动态暴露过滤（Middleware），模型输出永远被当作不可信数据。

### 练习 3：`create_agent` 减少了什么、带来了什么成本？

**答案：**减少了循环编排、消息历史和结构化解析的样板代码；带来了框架版本耦合、`context_schema`/`ToolRuntime`/stream_mode 等抽象学习成本，以及流式协议适配成本。安全边界、执行边界、评测指标仍需自己定义。

## 12. 面试追问

### 12.1 "迁移到 LangChain 后，代码少了多少？安全边界靠什么保证？"

回答框架：先给 M1/M2 对照——框架减少了循环编排、消息历史、结构化解析的样板；安全边界**一条没少**，越权拦截、动态暴露、执行边界、评测指标仍是自己写的确定性代码。结论：框架省的是编排样板，边界定义权从没让渡出去。

### 12.2 "你们怎么证明这些定量指标是真的，不是挑出来的？"

回答框架：指标由脚本在 ≥40 条数据集上自动统计并 `assert`，数据集分层覆盖直接回答/单工具/多工具/越权/循环/无权限；未达标自动失败并输出失败分类，不保留只挑成功截图的空间；每个样本保存 `query/dataset/model/prompt` 版本 + `run_id` 可复现。
