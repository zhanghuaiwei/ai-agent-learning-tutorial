# AI 服务与业务服务边界

> 第 21 周增强线｜结论：保留 Python 主线，Java 只承担值得保留的业务边界。

## 1. 为什么不是全 Java

你的目标是 AI Agent 应用开发，LangChain/LangGraph/LangSmith 的主流资料与生态以 Python 为主；每周学习时间有限，全面改用 Java 会稀释 Agent 深度。因此 Python 必须是 Agent 后端主线。

## 2. 为什么仍保留 Java

企业现有资产系统常是 Java。用一周建立最小业务服务，能证明你理解“AI 编排不能拥有一切”：

- Java 拥有设备、告警、工单、审批、事务和最终业务规则。
- Python 拥有模型网关、RAG、Graph、Prompt、评测和 Agent Tool Adapter。
- 两者通过版本化 REST 契约集成，不共享数据库表。

若时间不足，Java 线可降级为 OpenAPI + Mock Server 设计，不影响 Python 主项目完成；但不得为了“全栈”牺牲 M4～M6 的可靠性证据。

## 3. 数据所有权

| 数据 | 权威方 | Python 可保存 |
|---|---|---|
| 设备/告警 | Java | 只保存带时间的查询快照或引用 |
| 工单/审批 | Java | `work_order_id/approval_id` 与运行映射 |
| 文档索引 | Python 知识服务 | Chunk、向量、版本、ACL |
| Agent State | Python/LangGraph | 执行状态，不替代业务事实 |

## 4. 练习与答案

### 练习 1：Python 能否直接连 Java 的 MySQL 以省一次 HTTP？

**答案：**不建议。会绕过 Java 业务规则和事务，形成共享数据库耦合；通过受控 API 访问。

### 练习 2：何时可以完全去掉 Java？

**答案：**目标岗位明确纯 Python、时间不足或没有可展示的业务边界时。仍应在架构文档说明如何集成现有 Java 系统。
