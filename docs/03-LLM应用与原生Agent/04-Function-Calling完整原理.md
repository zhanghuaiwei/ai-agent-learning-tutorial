# Function Calling 完整原理

> 预计 7 小时｜目标：看懂“模型建议调用”与“系统真正执行”之间的边界。

## 1. 完整生命周期

模型收到消息和 Tool Schema → 输出工具名与参数 → 应用校验参数与权限 → 执行工具 → 把结果作为 Tool Message 回传 → 模型生成最终回答或继续调用。模型不会因为生成了工具调用就自动拥有系统权限。

Tool 描述应写清：用途、何时使用/不使用、参数单位、数据新鲜度、副作用、可能错误。名称采用动词加对象，如 `get_equipment_alarm`；不要把十种互斥行为塞进一个万能 Tool。

## 2. Tool 分级

| 级别 | 示例 | 控制 |
|---|---|---|
| 只读 | 查设备、搜手册 | 鉴权、限流、数据范围 |
| 可逆写 | 创建工单草稿 | 幂等、审计、可撤销 |
| 高风险写 | 派单、关闭告警 | 明确确认、审批、最小权限 |
| 禁止 | 绕过安全联锁 | 不向 Agent 暴露 |

返回结果使用小而稳定的结构，不把数据库整行或异常堆栈喂回模型。工具错误也要结构化：`code/retryable/safe_message`。

## 3. 项目任务

手写 `ToolRegistry`：注册 Schema、执行函数、权限、超时、副作用等级。实现只读查询与“创建草稿”，拒绝未知工具和额外参数。

## 4. 练习与答案

### 练习 1：模型说“用户已同意”能否当审批证据？

**答案：**不能。审批必须来自可信 UI/API 事件，关联用户身份、动作摘要、时间和幂等键。

### 练习 2：查设备工具为什么也要权限？

**答案：**只读不等于无风险，仍可能越权读取其他工厂资产或泄露敏感状态。

## 5. 验收与资料

工具执行前完成 Schema、身份、资源范围和副作用检查；重复写调用不重复建单。参考 [LangChain Tools](https://docs.langchain.com/oss/python/langchain/tools)、[OpenAI Function Calling 概念](https://developers.openai.com/api/docs/guides/function-calling)。
