# 手写 Agent Loop

> 预计 8 小时｜产出：不依赖框架的最小 ReAct 风格 Agent，以理解框架替你做了什么。

## 1. 循环

```text
初始化 messages、step=0
while step < max_steps and deadline 未到:
  调模型
  若为最终答案：验证并返回
  若为工具调用：校验 -> 授权 -> 执行 -> 记录 Tool Message
  否则：受控失败
超过步数/Token 上限/期限：停止并说明
```

停止条件至少包括：最终答案、最大步数、总时间、Token 上限、连续相同工具调用、用户取消、不可恢复错误、等待人工批准。费用只做 Usage 记录、单位任务分析和异常增长告警，不以教程累计金额终止正常学习调用。

## 2. 防失控设计

- 为每次动作生成 `step_id`，保留输入摘要、选择、结果、耗时和费用。
- 相同工具与规范化参数连续出现时触发循环检测。
- 工具结果过大时截断并保存引用，不直接塞回全部正文。
- 最终答案只能引用本轮可见证据，不能把内部 Chain of Thought 暴露给用户。
- 不要求模型输出隐秘推理过程；记录可审计的动作与简短决策原因即可。

## 3. 项目任务

实现最多 6 步的设备维护 Agent：可查告警、搜手册、创建工单草稿。用脚本模型精确模拟“直接回答、一次工具、多工具、未知工具、循环、超时”。

## 4. 练习与答案

### 练习 1：最大步数为何不是越大越好？

**答案：**步数扩大费用、延迟和副作用风险；合理上限应由任务轨迹数据决定，超限进入降级。

### 练习 2：是否应记录模型完整思维链用于调试？

**答案：**不需要，也不应把它作为审计依据。记录输入版本、工具选择、参数、结果、状态转移和简短理由即可复现行为。

## 5. 验收与资料

循环永远有界；未知工具不可执行；每步可观测；故障有明确终态。参考 [LangChain Agents](https://docs.langchain.com/oss/python/langchain/agents)、[OpenAI Agents 指南](https://developers.openai.com/api/docs/guides/latest-model)。
