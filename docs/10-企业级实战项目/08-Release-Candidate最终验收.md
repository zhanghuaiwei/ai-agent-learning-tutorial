# Release Candidate 最终验收

> 第 23 周｜目标：冻结作品集候选版本，最后一周只做面试演练和高优先缺陷。

## 1. 功能门禁

- 查询告警、维护知识带引用回答、证据不足拒答。
- 工单草稿、可信审批、暂停/恢复、幂等提交。
- 普通与 SSE API，取消、断线、错误协议明确。
- Fake 模式一键运行；真实千问/DeepSeek 可配置。

## 2. 质量门禁

- 普通测试、E2E、评测、红队全部有报告。
- Recall/忠实度/任务成功达到 M3～M5 门槛。
- 跨租户、无审批写入、重复工单三个指标均为 0。
- P95、每成功任务成本和费用异常增长告警可证明；无教程金额上限。
- 六类故障注入都有安全终态。

## 3. 工程门禁

无密钥与敏感样本；依赖锁定；CI 绿；Dockerfile 可构建；迁移、回滚、备份、Runbook 齐全；Prompt/Graph/索引/MCP 版本明确；License 与数据来源清楚。

## 4. 面试资产

准备 1/3/8 分钟项目表达、架构白板、五个失败故事、八份 ADR、完整评测报告、两次故障演示。简历数字必须能追溯到报告，禁止夸大线上规模。

## 5. 练习与答案

### 练习 1：RC 前发现低频严重越权问题，按时冻结还是延期？

**答案：**安全硬门禁失败必须修复或禁用相关能力，不能用低频作为接受理由。

### 练习 2：还有很多想做的功能怎么办？

**答案：**进入路线图，冻结范围；优先修关键缺陷、文档和演练，业务闭环与稳定性高于功能数量。

## 6. 签字清单

产品范围、架构、质量、安全、运维、成本、演示各项填“通过/例外/证据链接/负责人”。例外必须写风险、临时控制和截止日期。
