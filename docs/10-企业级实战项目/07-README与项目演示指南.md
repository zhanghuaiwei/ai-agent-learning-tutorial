# README 与项目演示指南

> 目标：让招聘方十分钟内理解价值、深度、运行方式和证据。

## 1. README 顺序

1. 一句话业务价值与明确边界。
2. 90 秒 GIF/视频或截图：引用、审批、恢复、Trace。
3. 架构图与数据所有权。
4. 核心能力：RAG、LangGraph、评测、安全、成本。
5. 快速开始：Fake 模式优先，不需要 Key/Docker。
6. 真实模型配置、Usage 与费用观测说明。
7. 测试/评测结果，链接完整报告。
8. 关键 ADR、Runbook、威胁模型。
9. 已知限制与路线图。

不要把技术栈徽章堆在业务问题前，不写无法证明的“企业级、高可用、零幻觉”。

## 2. 演示脚本

八分钟：问题与边界 45 秒；正常带引用诊断 90 秒；审批暂停/重启恢复 120 秒；注入或越权拦截 60 秒；成功后超时仍无重复工单 90 秒；评测/成本/架构取舍 75 秒。

准备离线 Fake 演示，避免面试现场网络和余额失败；真实模型视频作为补充。预置数据必须合法可公开。

## 3. 练习与答案

### 练习 1：演示应从代码目录开始吗？

**答案：**先从业务问题和用户结果开始，再钻到架构、Trace 和关键代码，招聘方更容易建立上下文。

### 练习 2：为何主动展示限制？

**答案：**体现边界意识和可信度，也能引导讨论下一步设计，而非被追问时才承认。

## 4. 验收

同事只按 README 可在 Fake 模式运行；演示不依赖临场输入；所有数字链接到可复现报告。
