# 系统架构、数据所有权与威胁模型

> 预计 8 小时｜目标：产出面试可白板表达的 C4 级架构与数据流；架构决策记录为 05 章 ADR 的输入。

## 1. 本章从哪里开始

01 章产出了一份需求基线：领域对象、状态机、不变量和 12+ 用户故事。但需求只说"要什么"，没说"放在哪、谁能碰、失败后发生什么"。本章承接 01 章，回答三个问题：

1. 系统由哪些容器组成，数据在它们之间如何流动？
2. 每份数据（尤其 Prompt、Trace、Checkpoint、向量库）的权威源是谁、谁能读写？
3. 每一条信任边界上，攻击者能做什么、我们如何控制、检测、并承认残余风险？

本章是第 10 阶段（企业级实战项目交付）的第二道工序，产出物直接喂给 05 章 ADR（架构决策）和 03 章测试（越权、注入、数据泄漏场景）。

完成后你应该能回答：

1. 模型供应商属于系统内部可信组件吗？向量数据库只存向量就无隐私风险吗？
2. 为什么 Prompt/Trace/Checkpoint/向量库常被数据所有权矩阵遗漏，却可能复制敏感内容？
3. Agent 特有威胁（间接注入、工具误用、身份混淆、记忆投毒）在传统 STRIDE 之外，为什么必须单独建模？

## 2. 本章完成标准（通过门槛）

必须同时满足：

- 产出 C4 的 System Context 与 Container 两层视图，另一位开发者能据此说出"每份数据在哪里、谁能写、失败后发生什么"；
- 数据所有权矩阵覆盖业务库、向量库、Checkpoint、Trace、Prompt、模型供应商六类存储，每类写明权威源、读写服务、租户键、加密、备份、保留、删除、审计；
- 每条信任边界列全认证、授权、加密、Schema、超时、限流、日志、失败语义八要素；
- 威胁清单每条有控制、检测和残余风险三列，不做"无残余风险"的空话；
- 架构决策点（如 Python Agent + Java 业务服务、RAG 选型、模型路由）用一句话标出，作为 05 章 ADR 的候选清单。

## 3. C4 视图

### 3.1 System Context（上下文）

```text
[维护工程师/值班负责人/知识管理员/审计]
        │ 浏览器 / 终端
        ▼
[智维 Agent 平台] ──只读/受控写──> [设备与工单业务系统（Java）]
        │
        ├──检索/生成──> [模型供应商（Qwen/DeepSeek）]
        └──文档摄取──> [文档源（手册/知识库）]
```

前端不是课程重点，只保留能快速实现的运行详情、证据、审批和反馈界面。

### 3.2 Container（容器）

```text
Web UI
  -> Python Agent API: auth context, SSE, LangGraph, RAG, policy, eval hooks
       -> Qwen/DeepSeek Gateway
       -> Knowledge Store / Checkpoint / LangSmith
       -> MCP Client -> Read-only Equipment MCP Server
       -> Java Business API -> Business DB / Outbox
```

每个箭头都是一条信任边界（见 §5），每条边界都要回答"谁认证、数据是否加密、Schema 谁定、超时多少、限流如何、日志记什么、失败语义是什么"。

## 4. 数据所有权矩阵

为每个存储写清八要素。特别检查 Prompt/Trace/Checkpoint/向量库，它们常被遗漏，却可能复制敏感内容：

| 存储 | 权威源 | 读写服务 | 租户键 | 加密 | 备份 | 保留 | 删除 | 审计 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Business DB | Java 业务服务 | Java 写，Agent 只读 | `tenant_id` | 传输 + 静态 | 是 | 按合规 | 逻辑删除 | 变更审计 |
| 向量库/知识索引 | 知识服务 | 摄取写，查询读 | `tenant_id` | 静态 | 可重建 | 版本化 | 下架即清 | 版本变更 |
| Checkpoint | Agent 服务 | Agent 读写 | `tenant_id` + `thread_id` | 静态 | 是 | 短周期 | 会话结束清 | 访问日志 |
| Trace/评测 | 观测平台 | 采集写，审计读 | `tenant_id` | 脱敏后存 | 是 | 按合规 | 定期清理 | 只读审计 |
| Prompt/版本 | 代码仓库/配置 | CI 发布 | 无租户键（全局） | 密钥加密 | Git 历史 | 永久 | 废弃标记 | 变更审计 |
| 模型供应商 | 外部处理方 | 仅 Agent 网关 | 最小化字段 | 传输加密 | 由供应商 | 见合同 | 数据最小化 | 调用日志 |

关键结论：**业务事实的权威源只有 Java 业务服务**，Agent 服务里的 Checkpoint/State 只是运行态，不承载业务真相；模型供应商是外部数据处理方，不能默认完全可信。

## 5. 信任边界与威胁

### 5.1 边界清单

| 边界 | 认证 | 授权 | 加密 | Schema | 超时 | 限流 | 日志 | 失败语义 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 浏览器 → Python | Token | 角色 Scope | TLS | 自有协议 | Deadline | 是 | request_id | 安全错误码 |
| Python → 模型供应商 | API Key | 最小字段 | TLS | 版本锁定 | 有限重试 | 是 | 调用计数 | 降级/安全失败 |
| 文档 → 索引 | 来源校验 | 知识管理员 | 传输 | 版本化 | Queue | 是 | 摄取任务 | 暂停新摄取 |
| MCP Server → Host | 受控连接 | 只读范围 | TLS | MCP 版本 | 是 | 是 | 工具调用 | 断连降级 |
| Python → Java | 服务间 Token | 资源授权 | TLS | OpenAPI | 分级超时 | 是 | 幂等键 | 查询与写分级 |
| CI → 制品 | 签名 | 最小权限 | 制品校验 | 依赖锁 | — | — | 构建日志 | 可回滚 |
| 管理员 → 配置 | SSO | 最小权限 | TLS | 配置校验 | — | 是 | 变更审计 | 配置回滚 |

### 5.2 STRIDE 辅助

用 STRIDE 快速过一遍经典威胁（伪造、篡改、抵赖、信息泄露、拒绝服务、提权），但重点放在 Agent 特有威胁上——传统 STRIDE 覆盖不到"模型被注入后把工具当武器"这类问题。

## 6. Agent 特有威胁

| 威胁 | 说明 | 控制 | 检测 | 残余风险 |
| --- | --- | --- | --- | --- |
| 间接注入 | 手册里藏指令诱导模型 | 工具只读范围、证据过滤 | 注入红队、引用审计 | 模型仍可能被诱导，靠确定性工具兜底 |
| 工具误用 | 模型用错工具/参数越权 | scope 检查 + 动态暴露 | 越权用例、无副作用断言 | 参数边界需持续维护 |
| 身份混淆 | 模型填 `tenant_id` 篡改身份 | 身份只来自服务端上下文 | 伪造 tenant 注入测试 | 依赖运行时注入正确性 |
| 记忆投毒 | 恶意文档污染长期记忆 | 无长期记忆、证据版本化 | 索引下架、版本审计 | 短期上下文仍可能被注入 |
| 数据外传 | 模型把敏感数据带出 | 最小化字段、脱敏 | 外发审计、供应商合同 | 依赖供应商合规 |
| 供应链 | 依赖/模型/MCP 被投毒 | 依赖锁定、制品签名 | 依赖扫描、版本审计 | 上游漏洞窗口期 |
| 无界调用消耗 | 恶意/失控请求烧 Token | 步数/Token/Deadline 上限 | 异常增长告警（仅观测） | 不设固定金额上限，靠告警止损 |

注意最后一条：费用控制只观测 Usage + 异常增长告警，不设固定金额上限——这是本项目的统一口径，避免用固定预算掩盖真实增长信号。

## 9. 常见错误与诊断顺序

### 9.1 把模型供应商当可信内部组件

错误：默认供应商"不会泄露"。诊断顺序：先确认它是不是外部数据处理方 → 检查是否最小化字段、确认合同/保留策略、密钥保护、超时与降级 → 做不到就按不可信处理。

### 9.2 认为向量库只存向量就无隐私风险

错误：只盯向量本身。诊断顺序：检查是否还存原文和元数据 → 向量本身是否可能泄露信息 → 补 ACL、加密、隔离和删除，而非只看向量字段。

### 9.3 威胁清单写"无残余风险"

错误：每条威胁都标"已完全控制"。诊断顺序：承认残余风险并写清"何时复审"，例如注入的残余风险是"模型仍可能被诱导，靠确定性工具兜底"，而不是"注入已根除"。

### 9.4 数据所有权矩阵漏了运行态存储

错误：只列业务库，漏 Prompt/Checkpoint/Trace。诊断顺序：把 Agent 特有存储单列，逐项补租户键、加密、保留、删除，因为它们是敏感内容的复制源。

## 10. 练习题与答案

### 练习 1：模型供应商属于系统内部可信组件吗？

**答案：**视为外部数据处理方；需最小化数据、确认合同/保留策略、密钥保护、超时与降级，不能默认完全可信。

### 练习 2：向量数据库只存向量就无隐私风险吗？

**答案：**通常还存原文和元数据，向量本身也可能泄露信息；仍需 ACL、加密、隔离和删除。

### 练习 3：为什么 Agent 特有威胁不能只靠 STRIDE？

**答案：**STRIDE 是通用系统视角，覆盖不到"模型被注入后把工具当武器""身份由模型填写导致混淆""记忆被投毒"等由概率生成引入的新攻击面。需在 STRIDE 之外单独建模，并把控制落在确定性代码（工具 scope、动态暴露、服务端上下文）而非 Prompt。

## 12. 面试追问

### 12.1 "你的架构里，业务数据到底存在哪？Agent 存的 Checkpoint 算真相吗？"

回答框架：业务事实唯一真相在 Java 业务服务（Business DB），Agent 服务的 Checkpoint/State 只是运行态、可重建。这样 Agent 故障不会污染业务数据，也能让"未审批不执行"由确定性代码而非模型状态保证。

### 12.2 "你们怎么防注入？"

回答框架：两层确定性兜底——工具只读范围 + 动态暴露（scope 检查），身份只来自服务端上下文；注入的残余风险靠注入红队和引用审计检测，而非依赖 Prompt 一句"忽略注入指令"。
