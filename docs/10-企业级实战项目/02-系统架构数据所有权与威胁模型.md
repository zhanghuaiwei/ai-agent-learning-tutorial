# 系统架构、数据所有权与威胁模型

> 预计 8 小时｜产出：面试可白板表达的 C4 级架构与数据流。

## 1. 容器视图

```text
Web UI
  -> Python Agent API: auth context, SSE, LangGraph, RAG, policy, eval hooks
       -> Qwen/DeepSeek Gateway
       -> Knowledge Store / Checkpoint / LangSmith
       -> MCP Client -> Read-only Equipment MCP Server
       -> Java Business API -> Business DB / Outbox
```

前端不是课程重点，只保留能快速实现的运行详情、证据、审批和反馈界面。

## 2. 数据所有权矩阵

为每个存储写：权威数据、读写服务、租户键、加密、备份、保留、删除、审计。特别检查 Prompt/Trace/Checkpoint/向量库，它们常被遗漏，却可能复制敏感内容。

## 3. 信任边界与威胁

边界：浏览器→Python、Python→模型供应商、文档→索引、MCP Server→Host、Python→Java、CI→制品、管理员→配置。每条边列认证、授权、加密、Schema、超时、限流、日志和失败语义。

采用 STRIDE 辅助，但重点是 Agent 特有威胁：间接注入、工具误用、身份混淆、记忆投毒、数据外传、供应链和无界调用消耗。

## 4. 练习与答案

### 练习 1：模型供应商属于系统内部可信组件吗？

**答案：**视为外部数据处理方；需最小化数据、确认合同/保留策略、密钥保护、超时与降级，不能默认完全可信。

### 练习 2：向量数据库只存向量就无隐私风险吗？

**答案：**通常还存原文和元数据，向量本身也可能泄露信息；仍需 ACL、加密、隔离和删除。

## 5. 验收

另一位开发者能根据图说出每份数据在哪里、谁能写、失败后发生什么；威胁清单有控制、检测和残余风险。
