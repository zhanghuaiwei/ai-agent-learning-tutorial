# 评测报告编写指南

> 目标：让面试官看到你用证据管理概率系统，而不是只展示 Demo。

## 1. 首页摘要

用一页回答：评了什么版本、面向什么任务、核心结果、是否达到门槛、最大风险、发布决定。所有百分比同时给分子/分母，避免“100%”来自两条样本。

## 2. 必备表格

| 分组 | 样本数 | 任务成功 | 检索 Recall@5 | 引用忠实 | 安全失败 | P95 | 元/任务 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 故障码 |  |  |  |  |  |  |  |
| 自然语言 |  |  |  |  |  |  |  |
| 无答案 |  |  |  |  |  |  |  |
| 注入/越权 |  |  |  |  |  |  |  |

同时展示基线/候选差异、重复运行方差、模型与数据版本。安全硬失败单独列出，不被平均分掩盖。

## 3. 失败案例

选 5～8 个代表案例：输入标签、期望、实际、错误层、Trace、根因、修复、回归样本、残余风险。不能只放成功回答。

## 4. 练习与答案

### 练习 1：报告中是否应放完整用户输入？

**答案：**只放自制或已脱敏数据；生产样本需按授权和隐私策略处理。

### 练习 2：没达到目标阈值是否不应展示？

**答案：**应诚实展示，并说明根因、风险和下一步。能管理失败比隐藏失败更体现工程能力。

## 5. 验收与资料

新读者只看报告即可判断能否发布并复现实验。参考 [LangSmith Evaluation](https://docs.langchain.com/langsmith/evaluation)、[Google ML Test Score](https://research.google/pubs/the-ml-test-score-a-rubric-for-ml-production-readiness-and-technical-debt-reduction/)。
