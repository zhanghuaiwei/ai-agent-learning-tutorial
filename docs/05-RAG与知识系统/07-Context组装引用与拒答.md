# Context 组装、引用与拒答

> 预计 7 小时｜产出：有证据才回答、引用可核验的生成层。

## 1. Context 组装

每段证据使用稳定标签：`[S1]`、标题、版本、页码、正文。按相关性、来源多样性与 Token 预算选择，删除重复片段；系统规则与证据用明显分隔，声明文档内指令不可执行。

引用不是在回答末尾随便列链接。每个可验证事实应绑定一到多个证据 ID；服务端验证 ID 确实存在于本轮 Context，再映射为用户可访问的来源。

## 2. 拒答设计

证据不足、证据冲突、无权限、问题超范围或高风险操作信息不足时，返回结构化拒答：缺什么、已查什么、用户可提供什么、是否建议人工。拒答率不是越低越好，应该与错误回答率共同衡量。

模型自报“置信度 95%”不可靠。置信策略来自检索命中、来源质量、一致性、任务类型和评测校准。

## 3. 项目任务

实现引用校验器和五种拒答码。用有答案、无答案、冲突、过期、越权各 10 条评测引用准确率与适当拒答率。

## 4. 练习与答案

### 练习 1：检索 Top1 分数很高就一定能回答吗？

**答案：**不一定。高分不代表包含完整答案，也不证明来源有效或无冲突；需结合证据覆盖和业务风险。

### 练习 2：引用 ID 合法就说明答案忠实吗？

**答案：**不是。还要判断引用内容是否真正支持相邻陈述，可用规则、人工和 LLM Judge 组合评测。

## 5. 验收与资料
