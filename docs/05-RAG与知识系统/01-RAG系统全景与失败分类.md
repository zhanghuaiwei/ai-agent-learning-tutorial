# RAG 系统全景与失败分类

> 预计 5 小时｜目标：把 RAG 视为可分层评测的数据系统，而不是“向量库 + Prompt”。

## 1. 全链路

```text
文档接入 -> 解析/清洗 -> 切分 -> 元数据/权限 -> Embedding/索引
用户问题 -> 查询理解 -> 召回 -> 过滤/融合 -> 重排 -> Context 组装
模型回答 -> 引用校验 -> 拒答/输出 -> 反馈与评测
```

三种典型架构：2-step RAG 固定先检索后生成，延迟稳定；Agentic RAG 由 Agent 决定是否及如何检索，更灵活也更难控；Hybrid 把查询改写、检索编排确定化，再允许少量动态工具。

## 2. 失败分类

- 接入失败：扫描 PDF、表格、页眉处理错误。
- 索引失败：切分丢语义、元数据缺失、权限串租户。
- 召回失败：正确片段没进入候选集。
- 排序失败：召回了但排不到前面。
- 组装失败：重复、超长、来源不清。
- 生成失败：证据足够却答错或伪造引用。
- 产品失败：问题超出知识范围却不拒答。

只有先定位层次，调参才有意义。

## 3. 项目任务

准备 20～30 份自制/可公开使用的维护文档，建立 50 条问题及标准证据 ID，画出 RAG 数据流和数据所有权。

## 4. 练习与答案

### 练习 1：回答错误就说明 Embedding 不好吗？

**答案：**不一定。可能是解析、切分、权限过滤、重排、Context 或生成问题，必须看每层指标和 Trace。

### 练习 2：何时优先 2-step RAG？

**答案：**知识问答路径固定、重视延迟和可预测性时；只有确需动态多次检索或调用其他工具才引入 Agentic RAG。
