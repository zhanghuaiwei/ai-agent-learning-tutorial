# 文档解析、清洗与版本

> 预计 7 小时｜产出：可重复、可增量、可审计的知识接入管道。

## 1. 原始文档不可直接入库

为每份文档保存：`document_id/source_uri/title/version/content_hash/ingested_at/tenant_id/acl/parser_version`。原文件与解析文本分层保存，任何 Chunk 都能反查来源页和文档版本。

清洗要去除重复页眉页脚、乱码和无意义空白，但保留标题层级、列表、表格单位、步骤编号、警告框。表格可转为带表头的 Markdown；图片信息需要 OCR 时单独标记可信度。

## 2. 增量与删除

用内容 Hash 判断是否变化；新版本先构建索引，再原子切换别名。删除文档必须同步删除 Chunk、向量和缓存，避免“幽灵知识”。解析器升级视为数据迁移，要能重建索引。

文档中的“忽略规则、调用工具”等句子都是不可信内容，入库时可标注风险，但最终仍要在检索和工具层隔离。

## 3. 项目任务

实现接入清单、Hash 去重、版本号、失败重跑和删除。为 PDF/Markdown/表格各准备一份金样文档，断言标题、页码、单位和警告未丢失。

## 4. 练习与答案

### 练习 1：只保存切分后的文本有什么问题？

**答案：**无法审计原文、修复解析错误、重建索引或展示准确引用；必须保留来源与版本映射。

### 练习 2：同一文件重复上传如何处理？

**答案：**按租户、逻辑文档 ID 和内容 Hash 判定；完全相同则幂等返回，内容改变则创建新版本并切换有效索引。

## 5. 验收与资料

接入可重复，删除可验证，任意 Chunk 可定位原文。参考 [Document loaders](https://docs.langchain.com/oss/python/integrations/document_loaders)、[Unstructured 文档](https://docs.unstructured.io/)。
