# Query 处理、过滤与基础检索

> 预计 6 小时｜产出：带租户、设备和时间过滤的检索服务。

## 1. 查询处理

用户问题可能含指代、省略和多个目标。可做：规范化型号/故障码、基于可信会话状态补全指代、拆分多问题、生成少量同义查询。改写必须保留原问题，并记录版本与结果。

先执行硬过滤再做语义排序：`tenant_id`、ACL、有效版本、设备类型、时间范围。不能让 LLM 生成任意数据库过滤表达式；把允许字段和操作符结构化。

## 2. 基础检索

先建立简单 Top-k 基线：向量召回 20 条，过滤与去重后取 5 条。k 过小可能漏召回，过大增加重排与上下文成本。对无相关结果应返回“证据不足”，不能总选最相近片段。

查询日志只存脱敏文本或 Hash、过滤条件、候选 ID、分数和耗时；必要时隔离保存原文并设置访问控制。

## 3. 项目任务

实现 `RetrievalRequest` 白名单过滤器、查询规范化和 Top-k 配置。设计同义词、错别字、跨型号、无答案、越权五类测试。

## 4. 练习与答案

### 练习 1：为什么权限过滤必须早于模型生成？

**答案：**敏感片段一旦进入上下文就已发生数据暴露，最终答案拒绝不能撤销。

### 练习 2：查询改写后效果变差如何定位？

**答案：**同时记录原查询和改写查询，各自跑召回并比较证据命中；不要只观察最终答案。
