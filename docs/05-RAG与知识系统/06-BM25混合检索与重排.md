# BM25、混合检索与重排

> 预计 7 小时｜产出：能同时找准故障码与自然语言语义的检索管道。

## 1. 为什么混合

向量检索擅长语义近似，关键词/BM25 擅长精确型号、错误码、零件号。工业知识同时需要两者。分别召回候选后，可用 Reciprocal Rank Fusion：按各列表排名而非不可比原始分数融合。

```text
RRF(d) = Σ 1 / (k + rank_i(d))
```

随后用 Cross-Encoder 或 LLM Reranker 对前 20～50 条重排，只把前 4～8 条交给生成模型。重排增加成本和延迟，因此要缓存并设超时降级。

## 2. 去重与多样性

同一文档相邻 Chunk 可能霸榜。按内容 Hash 去重，并限制单文档候选数；同时保留覆盖多个故障假设的证据。不要在重排前丢掉 ACL 元数据。

## 3. 项目任务

实现关键词、向量、RRF、可选重排四层。比较纯向量、纯 BM25、混合、混合+重排的 Recall@5、MRR、P95 和费用。

## 4. 练习与答案

### 练习 1：为何不能直接相加 BM25 分数和余弦分数？

**答案：**量纲与分布不同，结果受任意缩放影响；RRF 用排名融合更稳健，或在验证集上学习归一化。

### 练习 2：重排器失败是否整次问答失败？

**答案：**通常可降级到融合排序，但必须记录降级并对高风险问题更保守地拒答。
