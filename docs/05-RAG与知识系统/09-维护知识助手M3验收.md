## 2. 端到端实现骨架

先固定自己的数据契约，不让 Vector Store 或 LangChain Document 类型穿透整个应用：

```python
from typing import Protocol

from pydantic import BaseModel, Field


class RetrievalQuery(BaseModel):
    text: str
    tenant_id: str
    allowed_doc_ids: frozenset[str]
    top_k: int = Field(default=20, ge=1, le=50)


class Evidence(BaseModel):
    chunk_id: str
    document_id: str
    document_version: str
    title: str
    locator: str
    text: str
    score: float


class RetrievalResult(BaseModel):
    evidences: list[Evidence]
    index_version: str
    query_version: str


class Retriever(Protocol):
    async def search(self, query: RetrievalQuery) -> RetrievalResult: ...
```

`tenant_id/allowed_doc_ids` 来自可信 Principal 和 ACL 服务，不从用户 Prompt 抽取。Retriever Adapter 内部可以替换为本地存储、pgvector 或托管服务，上层契约不变。

完整请求按以下顺序执行：

```text
认证与 ACL
  → Query 分类/规范化
  → Dense 与 BM25 并行召回
  → ACL 二次断言
  → RRF 融合、去重、可选重排
  → Context 组装与注入隔离
  → 证据门槛判断
  → 结构化回答/拒答
  → 引用合法性校验
  → Trace、Usage 与评测记录
```

生成层使用明确 Schema：

```python
from typing import Literal


class Citation(BaseModel):
    evidence_id: str
    claim: str


class RagAnswer(BaseModel):
    status: Literal["answered", "insufficient_evidence", "forbidden"]
    answer: str
    citations: list[Citation]
    missing_information: list[str]
```

模型返回后执行确定性校验：所有 `evidence_id` 必须存在于本次 Context；每个引用的 Document 仍对 Principal 可见；`insufficient_evidence` 不允许伪造引用；高风险维修建议必须有对应安全规范证据，否则降级为请求人工确认。

## 3. 可重建摄取与稳定 ID

每个 Chunk ID 由稳定输入生成，例如：

```text
sha256(tenant_id + document_id + version + section_path + normalized_text)
```

摄取任务记录 `parser/chunker/embedding/index` 版本。新版本先构建到新索引，完整评测通过后原子切换 Alias；失败时回到旧版本。不要在原索引上边删边写，导致线上查询同时看到半新半旧数据。

最小摄取清单：

1. 原文件哈希、来源、权限和版本入库；
2. 解析正文与结构，保留页码/章节/表格位置；
3. 清洗重复页眉页脚，不删除安全警告和单位；
4. 切分后生成稳定 ID，检测重复与空 Chunk；
5. 写关键词索引和 Embedding；
6. 抽样核对原文与 Chunk；
7. 运行检索、安全和权限评测；
8. 切换 Active Index Version。

## 4. RRF 与重排实现要点

Dense、BM25 分数尺度不同，不直接相加。RRF 只依赖排名：

```python
from collections import defaultdict


def reciprocal_rank_fusion(
    ranked_lists: list[list[str]],
    *,
    rank_constant: int = 60,
) -> list[tuple[str, float]]:
    scores: dict[str, float] = defaultdict(float)
    for ranked_ids in ranked_lists:
        for rank, chunk_id in enumerate(ranked_ids, start=1):
            scores[chunk_id] += 1 / (rank_constant + rank)
    return sorted(scores.items(), key=lambda item: item[1], reverse=True)
```

重排只处理有限候选，例如融合后的 Top 20，再取 Top 5 进入 Context。比较四组 Baseline：BM25、Dense、RRF、RRF + Reranker。若重排没有稳定改善 Recall/MRR/引用或业务成功率，就不保留额外复杂度。

## 5. 失败分类与定位顺序

| 现象 | 先检查 | 不要先做 |
| --- | --- | --- |
| 标准证据不存在 | 原文、解析、版本和 ACL | 换更大模型 |
| 证据存在但未召回 | Query、Chunk、Embedding、BM25 | 调 Prompt |
| 已召回但未进入 Context | 去重、重排、Token 分配 | 增大 Top-K 到无限 |
| Context 正确但回答错 | Prompt、Structured Output、引用校验 | 重建索引 |
| 越权 Chunk 进入候选 | 检索前 ACL 和 Cache Key | 生成后删答案 |
| 恶意文档诱导 Tool | 文档隔离、Prompt 与 Tool 授权 | 相信“忽略文档指令”一句话 |

每个失败样本保存 `query/dataset/index/prompt/model` 版本和 Trace ID，使修复能在同一输入上复现。

## 6. 评测实现

数据集至少分层：精确型号、错误码、自然语言症状、多跳证据、无答案、冲突版本、过期文档、跨租户、间接注入。不能用同一个 LLM 同时无人工检查地生成题目、参考答案和评分。

检索指标：

```text
Recall@K = 至少一个标准证据进入 Top-K 的样本比例
MRR = 第一个标准证据排名倒数的平均值
ACL leakage = 未授权 Chunk 进入候选/Context 的次数
```

生成指标单独计算引用合法率、引用支持率、完整性、无答案拒答率和危险建议率。端到端任务成功率不能掩盖检索与生成哪一层退化。

## 7. 建议门槛

Recall@5 ≥ 90%；引用 ID 合法率 100%；引用忠实度 ≥ 90%；越权泄露 0；注入触发高风险工具 0；无答案适当拒答率 ≥ 90%。阈值要结合数据难度说明，不可用删难题达标。

## 8. 练习与答案

### 练习 1：指标达标但用户仍抱怨，怎么办？

**答案：**检查数据集代表性、用户分群、回答可读性和线上分布漂移；把脱敏反馈转为新样本，不盲目调模型。

### 练习 2：如何向面试官讲 RAG 优化？

**答案：**按失败分类讲基线、假设、单一变量实验、指标变化、成本/延迟取舍和遗留风险，而不是罗列组件名。

### 练习 3：把 Top-K 从 5 调到 50，Recall 提高，能直接上线吗？

**答案：**不能。还要检查 Context 噪声、延迟、Token、引用忠实度和权限风险。可让召回层 Top-K 较大，再经融合/重排/证据门槛只送少量高质量 Chunk。

### 练习 4：为什么 ACL 泄漏要在候选层就记为失败？

**答案：**未授权内容一旦进入重排、Trace 或模型 Context 就已经扩大泄漏面，不能依赖最终答案碰巧没展示。
