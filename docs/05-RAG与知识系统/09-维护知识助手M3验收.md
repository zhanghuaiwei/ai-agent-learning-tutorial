# 维护知识助手 M3 验收

> 第 11 周里程碑｜目标：交付可追踪引用、权限隔离和可量化质量的 RAG 服务。

## 1. 必交能力

- 版本化接入、结构感知 Chunk、可重建索引。
- 关键词 + 向量 + RRF，可选重排与降级。
- 租户/ACL 过滤、Context 预算、引用校验、结构化拒答。
- 至少 80 条分层评测，含无答案、冲突、注入和越权。
- 数据/Prompt/模型/索引版本随每次结果记录。

## 2. 建议门槛

Recall@5 ≥ 90%；引用 ID 合法率 100%；引用忠实度 ≥ 90%；越权泄露 0；注入触发高风险工具 0；无答案适当拒答率 ≥ 90%。阈值要结合数据难度说明，不可用删难题达标。

## 3. 练习与答案

### 练习 1：指标达标但用户仍抱怨，怎么办？

**答案：**检查数据集代表性、用户分群、回答可读性和线上分布漂移；把脱敏反馈转为新样本，不盲目调模型。

### 练习 2：如何向面试官讲 RAG 优化？

**答案：**按失败分类讲基线、假设、单一变量实验、指标变化、成本/延迟取舍和遗留风险，而不是罗列组件名。

## 4. 演示

演示精确故障码、自然语言同义问题、冲突文档、无答案拒答、恶意文档与权限隔离；最后打开评测报告解释一次失败修复。

M3 通过后再进入 LangGraph。RAG 本身不稳定时，多节点只会让根因更难定位。
